MiniMax M2：推理经济学的三板斧

一个总参数上百 B 的 MoE 模型，单次推理只激活十几 B 的参数——剩下的 80% 参数，是摆设吗？

不是。它们是"备选专家"，平时待命，遇到对口问题才上场。这个设计背后是一次计价规则的改写：推理成本不再按"你有多少参数"算，而按"你激活了多少参数"算。理解这一点，就理解了今年开源推理模型的全部打法。

一、先算账：推理成本碾压训练成本

训练：一次性投入，几百万到上千万美元，烧完就没了
推理：持续失血，每 1M tokens 烧一次，一年烧掉训练成本的 10 倍

模型发布那天，真正的花钱才刚刚开始。所以今年竞争的主战场从"谁训得更大"转向了"谁跑得更便宜"。推理成本拆开就三块：算力（FLOPs）、显存（KV Cache 和权重）、延迟（用户愿意等多久）。下面的三板斧，刀刀砍在这三块上。

二、稀疏激活：显存按总量交税，算力按激活量交税

MoE 把 FFN 层换成 N 个"专家"，每次只选 top-k 个激活：

总参数 100B，64 个专家，每次激活 8 个
→ 显存占用：100B（权重都得加载）
→ 计算量：约 13B（只算激活的部分）

用显存换"知识容量"，用稀疏换"计算便宜"。 参数规模上去了（模型更聪明），单次推理的 FLOPs 没上去（跑得不贵）。

但有两个税：通信税——专家分布在多卡上，token 路由的 All-to-All 通信，小规模部署时可能吃掉稀疏的全部收益；负载不均衡税——热门专家挤爆、冷门专家闲置，拿工程复杂度换便宜。

三、KV Cache：推理模型的隐形杀手

推理模型的特点是思考过程很长：答案 500 token，思考可能 8000 token。而解码时每个历史 token 的 Key/Value 都要缓存在显存里。算一笔账：

70B 模型，80 层，hidden dim 8192，FP16
单个 token KV ≈ 2 × 80 × 8192 × 2B ≈ 2.6MB
8K 思考过程 × 2.6MB ≈ 21GB —— 吃掉一张 4090 的几乎全部显存

还没算 batch。并发 8 个请求就是 168GB，直接爆显存。所以有三层手段：GQA（多 Query 头共享 KV 头，砍到 1/4~1/8，现在是标配）；KV 量化（FP16→INT8，显存再砍半，配合 vLLM 的 PagedAttention 收拾内存碎片）；MLA（DeepSeek 路线，把 KV 压缩到低秩 latent 向量，降一个数量级）。

记住这个公式：推理模型的并发能力 ≈ 显存 / 单请求 KV Cache。KV 砍一半，并发翻一倍——最直接的降本。

四、推测解码：把 5 次串行访存合并成 1 次

自回归生成的瓶颈在访存不在计算：每生成一个 token，都要把几十 GB 权重从显存读一遍，计算单元大部分时间在等数据。这叫 memory-bound。

# 推测解码：小模型猜，大模型验
draft_tokens = draft_model.generate(prompt, n=5)   # 小模型快，一口气猜 5 个
accepted = target_model.verify(prompt, draft_tokens) # 大模型并行验证，一次访存
# 猜对的留下，猜错的从第一个错位重来

大模型"想"得慢，但"验"得快。加速的本质，是把 5 次串行访存合并成 1 次。 实测 2~3 倍提速。对推理模型尤其有效：思考过程的 token 往往模式化、可预测，draft 猜中率高。部署推理模型不配推测解码，等于开着跑车挂一档。

五、Prefill vs Decode：两种瓶颈，两种打法

Prefill：prompt 一次性喂入，算 KV —— 计算密集，瓶颈在 FLOPs，决定首 token 延迟
Decode： 一个 token 一个 token 吐 —— 访存密集，瓶颈在显存带宽，决定生成速度

推理模型的特殊性：思考过程让 decode 极长，一个 8000 token 的思考，decode 时间可能是 prefill 的 50 倍。90% 的优化精力应该花在 decode 上——KV 压缩、推测解码、continuous batching（vLLM 的动态调度：一个请求结束立刻塞新请求，不等整个 batch，吞吐再抬 2~4 倍），全是为 decode 服务的。

结语

一套"推理经济学"拉满的部署长这样：

MoE 稀疏激活（省算力）× KV 压缩（省显存）× 推测解码（省访存）× continuous batching（省等待）

四个乘数叠加，就是开源推理模型敢跟闭源拼成本的底气。80% 待命的参数不是摆设——它们是"知识库存"，平时不花钱，只占货架。推理经济学的精髓，就是把"聪明"和"贵"解耦。

自部署时按这个顺序：先算 KV（并发不够后面白搭）→ 选量化（2×4090 级别直接 INT4/FP8）→ 开推测解码（白捡 2~3 倍）→ 压测 decode 延迟 → 最后算总账对比 API 价格。
