做硬件的朋友半夜甩来一张电路板照片："通电就冒烟，帮我看看哪的问题？"我丢给视觉推理模型。两分钟后它回的不是"这是一块绿色电路板"，而是："左上角第三颗电容顶部鼓包；顺着走线往下有处铜箔发黑疑似烧蚀；建议断电测电容两端对地阻值。"它没有"描述"这张图，它"检查"了这张图。

视觉推理：模型第一次"看"着思考

做硬件的朋友半夜甩来一张电路板照片："通电就冒烟，帮我看看哪的问题？"我丢给视觉推理模型。两分钟后它回的不是"这是一块绿色电路板"，而是："先看左上角，第三颗电容顶部鼓包了；顺着它旁边的走线往下，有一处铜箔颜色发黑，像是烧蚀；建议先断电，测这颗电容两端对地阻值。"

它没有"描述"这张图，它"检查"了这张图。看一眼，想一步，再看一眼，再想一步——这就是视觉推理：模型第一次开始"看"着思考。

一、从"看图说话"到"看图思考"：token 流的结构变化

传统 VLM：[图像 tokens] → [文本 tokens]      （单向：先看后说）
视觉推理：[图] → [想] → [回看放大] → [想] → [结论]  （交错）

区别不在"看"，在"想"。前者是感知：像素翻译成文字，一次性输出。后者是感知和推理的交织：模型在视觉 token 和文本 token 之间来回跳——看一眼图，想一步，发现信息不够，再看一眼，接着想。

类比人类做几何题：眼睛在题目图和草稿纸之间来回扫。你不会"先看完图、闭上眼睛、一口气写完证明"。边看边想，是智能的自然工作方式——模型只是在补上这一课。

二、核心能力：主动"回看"

视觉推理的核心能力只有一个：主动回看。推理到关键步骤时，重新把注意力放回图像相关区域，而不是靠第一眼的模糊印象往下编。

实现起来是三个硬骨头：

什么时候回看：不是每步都回看——太贵了。模型要判断"当前这步需不需要视觉证据"。这和 Agent 的"什么时候调用工具"是同一个决策问题：把"看图"当成一种可主动调用的感知工具，而不是一次性输入。

回看哪里：粗看全图定位可疑区域，再对局部高分辨率裁剪、重新编码。人类检查电路板"先扫全貌，再凑近看"，模型也需要这种由粗到精的注意力调度。

怎么训练：训练数据是"视觉思维链"——每一步绑定"看了哪里、想了什么"。标注员不仅要给答案，还要记录视线轨迹和思考过程，标注成本极高。

三、为什么是现在：三个前提刚刚凑齐

上下文够长：交错推理的 token 消耗是纯文本 3-5 倍（图像反复编码+思考展开），没有 128K 起步的窗口，"边看边想"在物理上展不开。

原生多模态架构：拼接式（vision encoder + LLM 简单拼接）做不好交错——重新走一遍 encoder 又贵又糙。原生架构里视觉 token 和文本 token 是同一种 token 空间，注意力直接指回原图区域，交错天然成立。

RL 奖励对了：最关键的一跃。用"答案对不对"做奖励，模型自己学会"什么时候该回看"。聪明的从来不是"教"，是奖励函数的设计。

四、三个硬伤：先别急着鼓掌

幻觉定位：模型说"左上角第三颗电容鼓包"，框出来的位置和说的对不上——嘴上头头是道，手指的却是别处。语言推理和视觉定位是两套系统，"说"和"指"对不上是最常见的翻车。

注意力漂移：推理链一长，模型"忘了看图"，后面几步靠语言惯性往下编。人类走神时知道自己走神了，模型不知道。

评测困境：传统 VQA 只看答案对错，但视觉推理的价值恰在"过程"。答案蒙对、过程全错，和过程全对、最后一步算错，哪个更"会"视觉推理？我们还没有好的"过程评测"，而没有评测就没有迭代方向。

结语：给工程师的三条实践建议

让模型"先描述，再下结论"：prompt 强制要求先说出看到了什么（位置、外观、数量），再开始推理。描述和结论分离，"指不对"的幻觉更容易被发现——把"看"和"想"解耦，错在哪一步一目了然。

要求可验证的输出：能框选就框选，能给像素坐标就给坐标。把"看"的过程变成可检查的 artifact。可验证性，是对抗幻觉定位最直接的武器。

别让它当"第一发现人"：医疗、工业等高风险场景，正确姿势是"第二双眼睛"——传统 CV 或规则先筛一遍，视觉推理负责解释和复核。

让它解释"为什么"，比让它决定"是什么"更安全。

最后留个问题：下次把图发给模型，多追问一句——你刚才说的细节在图的哪个位置？能框出来吗？框得出来，它是真"看见"了；顾左右而言他，那它只是在用语言的流畅，掩盖视觉的缺席。
