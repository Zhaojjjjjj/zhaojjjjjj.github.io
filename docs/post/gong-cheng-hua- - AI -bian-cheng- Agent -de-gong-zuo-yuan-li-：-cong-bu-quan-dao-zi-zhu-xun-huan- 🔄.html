工程化 - AI 编程 Agent 的工作原理：从补全到自主循环 🔄

2025 年春天，AI 编程从"补全"跨进了"自主循环"时代：Cursor Agent、Claude Code 让模型自己读文件、改代码、跑测试。这篇拆开这个循环，讲讲它到底是怎么转起来的，以及工程上真正的难点在哪。

从补全到循环：范式变了

Copilot 时代：tab 补全，模型是"高级输入法"。

Agent 时代：你给一个目标（"把登录页的暗色模式修了"），模型自主规划、执行、验证。核心是一个循环：

while not done:
    observation = 感知（读文件、看报错）
    thought     = 推理（下一步干什么）
    action      = 行动（调工具：读/写/跑命令）

这就是 ReAct（Reason + Act）模式，2022 年的论文，2025 年的工程。

循环的四个部件

  1. 工具（Tools）：read、write、edit、bash、grep。Agent 的"手"。工具设计是门艺术：粒度太粗（"重构整个项目"）模型hold不住，太细（每次只读一行）token 烧不起。
  2. 上下文管理：每次循环都把历史塞进 prompt，窗口再长也会爆。Claude Code 的解法是自动 compaction：上下文快满时，让模型自己总结一份备忘录，然后开新窗口继续。这是 2025 年 Agent 工程最重要的 trick 之一。
  3. 终止条件：什么时候算"做完了"？靠模型自己判断 + 规则兜底（最大步数、测试通过）。无限循环是真实发生过的 bug。
  4. 验证闭环：跑测试、看 lint。没有验证的 Agent 就是在随机改代码——"能跑"和"跑对"是两回事。

为什么 2025 年才爆发

三个条件同时成熟：

  • 模型 tool calling 可靠性：Sonnet 3.7/4 的工具调用准确率过了可用线。之前的模型调工具像扔骰子。
  • 长上下文：200K 上下文让 Agent 能"记住"整个任务现场。
  • MCP：工具生态标准化，Agent 的"手"变多了（见上一篇）。

工程上的真难点

  1. 上下文污染：一次失败的尝试会污染后续推理。好的 Agent 要会"遗忘"——把死胡同的探索从历史中摘掉。
  2. 成本：一个复杂任务烧掉几十万 token 是常态。按量计费下，Agent 的 ROI 需要仔细算。
  3. "70% 问题"：Agent 能搞定 70% 的任务，剩下 30% 需要人接手——而判断"这 30% 是哪部分"本身就需要专家。
  4. Review 负担：AI 一分钟写 500 行，你 review 要半小时。生成速度和审查速度的剪刀差，是 Agent 落地最大的隐性成本。

一句话总结

AI 编程 Agent 的本质是"ReAct 循环 + 工具 + 上下文工程"。2025 年的爆发不是某个单点突破，而是模型可靠性、长上下文、工具生态三条曲线同时越过可用阈值。但别被 demo 骗了：真正的成本不在生成，在 review——而这一点，短期内不会变。
