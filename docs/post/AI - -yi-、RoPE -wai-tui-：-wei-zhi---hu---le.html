AI - 一、RoPE 外推：位置"糊"了

"能装下"不等于"记得住"。1M 上下文的"无损"，要过位置、注意力、数据三关。

先说为什么"有损"是默认状态。三个原因，一个比一个根本：

一、RoPE 外推：位置"糊"了

位置编码（RoPE）是训练时只见过 32K 的"尺子"。推理时拉到 1M，等于拿 30 厘米的尺子量 10 米——刻度不够用了。

训练：位置 0..32767，每个位置有清晰的旋转角度
推理：位置 500000 → 角度超出了训练分布 → 模型分不清 500K 和 501K

位置"糊"了，模型就分不清"谁在前谁在后"——长文档的顺序信息直接丢失。这是"有损"的第一来源。

GLM-5.2 的解法是 YaRN 位置插值：不是外推，是重标刻度。把 RoPE 的旋转频率重新映射，让 1M 个位置每个都有区分度。关键区别：外推是"硬撑"，插值是"重训"——位置编码本身要为长上下文重新学习，不能指望训练时的尺子直接能用。

二、注意力稀释：softmax 的分母太大了

# 1M 个 token 的 softmax
attn_weights = softmax(scores)  # 分母是 100 万项的和
# 每个 token 分到的权重 ≈ 1/1M ≈ 0

注意力被摊薄到接近于零。模型"看"了 1M 个 token，但每个都没看清——就像把一滴墨水分到一吨水里。

解法是注意力下沉（Attention Sink）：保留开头的几个 token 作为"锚点"，让注意力有地方"落脚"。这个发现来自 2023 年的论文（StreamingLLM），2026 年成了标配。原理很反直觉：softmax 需要一些"垃圾桶"token 来吸收多余的注意力质量，否则所有权重都被摊平。有了 sink，重要的 token 才能凸显出来。

三、训练没见过：分布外的 1M

模型训练时：最长见过 100K
推理时：扔进去 1M
→ 分布外（OOD），表现崩

前两个是架构问题，这个是数据问题——而且是最难解决的。1M 长度的训练数据从哪来？整个代码仓库、超长文档、书籍——得真有那么长的、有意义的文本，而不是把 10 篇短文拼起来（拼接的文本没有长程依赖，训了白训）。

GLM-5.2"专注 Coding 与长程任务"的定位，在这里露出了用意：代码仓库天然就是长程数据——一个 50 万行的 monorepo，跨文件引用就是最真实的长程依赖。用代码训长上下文，比用文档靠谱得多。

四、"无损"的验证：大海捞针的中段

测试：在 1M tokens 里藏一句话，5 个位置各藏一次
GLM-5.2：0%、25%、50%、75%、100%，全部 95%+ 召回
有损模型：两端 90%，中间掉到 60%

看中段分数，不看窗口数字。 "支持 1M 上下文"是个营销数字，"1M 的中间位置能找回 95%"才是工程指标。2026 年选长上下文模型，只看这一行。

结语：对 Agent 的意义

Agent 任务：读 50 万行代码库，找 bug
有损：读到后面忘了前面 → 循环读，浪费 token，成本 ×3
无损：一次读完，全记住 → 直接定位

2026 年，上下文的竞争从"多长"转向"多真"——装得下是及格，记得住才是优秀。

而"多真"的三要素（位置插值、注意力下沉、长程训练数据），没有一个是"把窗口调大"能解决的。长上下文不是参数，是系统工程。
