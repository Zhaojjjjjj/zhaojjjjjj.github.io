AI - Midjourney V1 图生视频：I2V 的技术路线 🎬

2025 年中，视频生成赛道有个 conspicuous 的分叉：Sora、Veo 们在卷"一句话生成电影"——文本到视频（T2V），越全能越好；Midjourney 却反着来，第一款视频模型 V1 只做图生视频（I2V）：给你一张图，让它动起来。看似保守，实则是一次精准的卡位。这篇讲讲 I2V 的技术路线，以及为什么"少做一点"反而是更难的取舍。

两条路线，两种世界观

T2V 的世界观是"从零创造"：用户一句话，模型同时解决画什么（内容）和怎么动（运动）两个问题。Veo 3 的 demo 里，"宇航员在火星上骑马"这种镜头，内容和运动都是模型凭空变出来的。浪漫，但代价是两个难题耦合在一起：画面崩了不知道是内容没学好还是运动没学好，prompt 要同时描述画面和动作，调参空间巨大。

I2V 的世界观是"分工"：画什么，交给用户（或上一环节的生图模型）；模型只解决怎么动。 首帧就是 MJ 级别的出图，审美下限被锁死，prompt 只需要描述动作——"镜头缓缓推近，云在飘"。模型的学习任务从"文本→画面→运动"坍缩成"静帧→动帧"，难度降了一个量级。

这个分叉背后是两种产品哲学。T2V 赌的是"通用"：一个模型搞定一切，工作流越短越好。I2V 赌的是"链条"：承认创作是多环节的，每个环节用最好的工具。2025 年中的创作者真实工作流证明了后者——几乎没人直接用 T2V 的 raw 输出成片，专业流程都是"T2V/MJ 出图 → 挑一张最好的 → I2V 动起来 → 剪辑软件精修"。MJ V1 卡的，正是这条链上附加值最高的一环。

I2V 的技术原理：首帧是一个强条件

I2V 的核心是一个条件扩散过程：

输入：首帧图像 I₀ + 运动描述 prompt P
输出：视频帧序列 I₀, I₁, …, Iₙ

拆开看有四个关键设计：

1. 图像编码：首帧进 latent。 首帧经 VAE 编码成 latent，拼进每一个去噪步骤的条件。这不是"参考图"式的弱引导，而是每一帧的生成都要以首帧 latent 为锚。类比：T2V 是闭卷考试，I2V 是开卷——答案（画面）就摆在桌上，模型只负责"续写动作"。

2. 运动先验：学的是帧间差异。 训练数据虽然是视频，但监督信号集中在帧怎么变，而不是帧长什么样。模型学的是光流、形变、遮挡关系这些"运动的语法"，而不是"猫长什么样"。这就是为什么 I2V 模型可以比 T2V 小得多——它根本不需要记住世界的样子，只需要记住世界怎么动。

3. 首帧锚定：高权重防跑偏。 去噪时首帧 latent 的条件权重极高，后面帧的生成被强约束在"长得像首帧"的流形附近。这是 I2V 比 T2V 稳定的根本原因——T2V 的第 50 帧可能已经不认识第 1 帧了（人物 identity 漂移是 T2V 的老大难），I2V 的每一帧都在"回头看"首帧。

4. 时序注意力：运动的连贯性。 帧与帧之间用时序注意力建模，保证运动平滑。这里有个精妙的 trade-off：时序窗口越大，运动越连贯，但显存和计算量平方级涨。V1 时代的 I2V 通常在"短时连贯"上做到极致（几秒内天衣无缝），长视频则靠"首帧→尾帧"的分段生成再拼接。

运动控制的粒度：I2V 真正的护城河

很多人把 I2V 理解成"让图片动起来"，低估了"怎么动"的控制维度。实际产品中，运动控制至少分三层：

  • 全局运镜：推、拉、摇、移、环绕。这是最好学的——本质是 2D/3D 变换，数据也好构造（对静态图做仿射变换就能造训练对）。
  • 局部动作：人物眨眼、挥手，云飘、水流。这需要真正的运动先验，是 I2V 模型的核心能力。
  • 物理交互：水花溅起、布料飘动、碰撞形变。这是最难的，2025 年中的 I2V 在这里还经常穿帮——因为单张首帧不包含物理材质信息，模型只能靠"看起来合理"来猜。

MJ V1 的聪明在于：它把宣传和能力对齐在自己最强的两层（运镜 + 局部动作），不去碰物理交互的硬骨头。用户用"镜头语言"的 prompt 就能得到惊艳结果，而不会因为"让两个人打一架"这种需求失望。能力边界的管理，本身就是产品设计。

首帧锚定的代价：I2V 的阿喀琉斯之踵

强条件是 I2V 的力量来源，也是它的天花板。三个代价在 2025 年中都还无解：

代价一：垃圾进，垃圾出。 首帧决定了视频 90% 的信息量——构图、光影、材质、人物长相。首帧有瑕疵（多一根手指、背景穿帮），I2V 会"忠实"地把它动起来，瑕疵一帧不落。这就是为什么专业工作流里"I2V 之前必有选图环节"：I2V 把"审美判断"外包给了人，模型只负责执行。T2V 至少还能靠重抽解决，I2V 的质量上限在你按下生成键之前就已经定了。

代价二：首帧与运动的矛盾。 首帧是静态的，但运动需要"未见的信息"：一张侧脸照，你想让他转过头来正对镜头——转过去的那半张脸，首帧里根本没有。模型只能靠先验"脑补"，脑补就崩。这是所有 I2V 的共有边界：运动幅度越大，对未见信息的脑补越多，穿帮率越高。所以 V1 时代惊艳的 demo 全是"小幅运动"（云飘、眨眼、缓慢推镜），大幅动作（转身、打斗）基本没人敢演示。

代价三：长视频的拼接缝。 单次生成通常只有几秒，做长视频要"首帧→尾帧"分段生成再拼接。拼接处的运动连续性和人物一致性，是另一个深坑。2025 年中的解法是"重叠生成 + 插值"，能做到"看不太出来"，但做不到"天衣无缝"。长叙事视频，依然是 T2V + 剪辑的领地。

认清这三个代价，才能理解 MJ 的产品克制：V1 的时长、运动幅度、prompt 形式，全都收敛在"首帧锚定最擅长"的区间里。不碰自己搞不定的，本身就是一种技术判断。

I2V vs T2V：不是替代，是分工

维度 I2V（MJ V1 路线） T2V（Sora/Veo 路线）
首帧质量 用户给定，上限极高 模型生成，靠抽卡
可控性 强（画面已定，只调动作） 弱（prompt 同时管画面和动作）
创意空间 小（只能在给定画面里动） 大（从零创造世界）
训练成本 小一个量级（只学运动） 巨大（内容+运动一起学）
典型翻车 动作不自然、物理穿帮 人物漂移、画面崩坏
工作流位置 精修环节 探索/头脑风暴环节

2025 年中的行业共识是：两条路线收敛到同一条工作流的两端。T2V 负责"从 0 到 1"的创意探索——快速生成几十个分镜概念；I2V 负责"从 1 到 100"的精修——把选定的那张图变成可用的镜头。做 T2V 的厂商后来全都补了 I2V 功能（Veo、Runway、Luma 一个没落下），反过来证明了 MJ 路线的判断：用户最终要的不是"生成视频"，是"把我想要的画面动起来"。

对开发者的三点启发

1. 做减法是竞争力。 MJ 没有追 Sora 的"全能"，而是把"静帧→动帧"这一个子问题做到极致。在 AI 产品里，"少做一点但做到最好"经常 beating "什么都做但都 80 分"——因为用户的工作流是链式的，链上每个节点都会选该节点最好的工具，而不是选一个全能但平庸的。

2. 强条件意味着小模型。 首帧这个强条件，让 I2V 可以用小得多的参数达到可用效果。这对端侧/低成本视频生成是真正的希望：当条件足够强，模型就不需要"记住世界"，只需要"理解变化"。2025 年中已经能看到这个趋势的早期信号——开源社区的 I2V 模型在消费级显卡上就能跑出可用结果，而同等质量的 T2V 还在吃 A100 集群。这个思想可以迁移——任何生成任务，先问"能不能给模型一个强锚点"，再问"模型要多大"。锚点越强，模型越小，成本越低，这是条被低估的 scaling 路线。

3. 卡链条，不做大而全。 用户要的不是"一个模型"，是"一条链"。MJ V1 的定位是"生图和剪辑之间的那个环节"，它甚至不需要自己的流量入口——MJ 的出图用户天然就是 V1 的用户。找链条上"价值最高、切换成本最高"的节点卡位，比从零造一条链聪明得多。更狠的是，I2V 的用户一旦在你的工具里调好了运动参数，迁移到别家的成本极高——卡位卡的不仅是价值，更是粘性。

回到开头那个分叉。Sora 们赌的是"一句话生成一切"的终局，MJ 赌的是"每个环节都有最好的工具"的现实。2025 年中的答案是：终局也许很美，但人们愿意付费的，永远是今天工作流里最好用的那一环。有意思的是，分叉并没有持续太久——T2V 厂商后来全都补上了 I2V，因为用户用脚投票：探索可以靠 T2V 碰运气，但交付必须靠 I2V 的确定性。MJ V1 选了"让图动起来"，然后把它做到了最好——保守的外表下，是最激进的产品判断。
