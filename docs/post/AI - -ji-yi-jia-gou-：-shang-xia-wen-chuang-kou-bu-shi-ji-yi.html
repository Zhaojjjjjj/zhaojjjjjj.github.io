AI - 记忆架构：上下文窗口不是记忆

朋友的 AI 编程助手陪他重构了三周：知道他用 Go 不用 Python，知道他讨厌 ORM，知道祖传 utils.go 谁都别碰。某天他开了个新会话问"看看这个项目的测试覆盖率"，助手回："请问这是什么项目？用什么语言？"——三周的默契，一次新会话，全部清零。

记忆架构：上下文窗口不是记忆

这不是某个产品的 bug，是行业现状：我们给 Agent 接了最强的模型、配了最多的工具，却忘了给它"记忆"。一个没有记忆的 Agent，不管多聪明，都只是昂贵的单次函数调用。

最常见的误解是：把上下文窗口拉长，就等于给了 Agent 记忆。 上下文窗口是工作台，不是档案室，三个致命缺陷：

  1. 关掉就清空——会话结束一切消失，三周默契就是这么没的；
  2. 长度不等于重要性——窗口越大关键信息淹没越快，"大海捞针"测试反复证明中间位置的信息模型经常"看不见"；
  3. 没有时间感——分不清"上周说的"和"刚才说的"，FIFO 式遗忘里"用户过敏史"和"昨天寒暄"被一视同仁地扔掉。

真正的记忆系统要回答三个问题：记什么、怎么记、什么时候忘。围绕这三个问题，业界走出三条路线。

一、路线一：超长上下文——暴力美学

最直接：把所有东西塞进 prompt——文档、三个月聊天记录、工具结果，1M 上下文全看。

prompt = [系统指令] + [三个月聊天记录] + [项目文档] + [当前问题]

优点是简单粗暴，一个 API 参数的事。缺点有三：贵（1M tokens 单次几块钱，高频 Agent 一天烧掉比服务器还多）；注意力稀释（塞 100 页文档，恰恰没看到第 37 页那行关键配置）；FIFO 遗忘（没有重要性概念）。

暴力路线适合一次性长文档任务：读财报、审合同。但凡需要"跨会话"，它就露馅。

二、路线二：RAG——外挂硬盘，但不是记忆

问题 → 向量检索 → 最相关的 10 个片段 → 塞进 prompt

RAG 是"查资料"，不是"学习"，三个天花板：

第一，检索质量决定一切。 "上次那个部署问题"和"kubectl apply 报 ImagePullBackOff"，向量相似度可能低得可怜——用户提问的措辞和记录时的措辞完全不同。

第二，碎片化。 10 个散片段，模型自己拼，跨文档推理经常断——每个片段都对，拼在一起是错的。

第三，没有沉淀。 下次问同样问题再查一遍。RAG 的记忆是"每次现查"，不是"学会记住"。

RAG 适合知识库问答。但"我朋友的重构助手"这个场景里，RAG 能回答"这个函数干嘛的"，回答不了"他喜欢手写 SQL"——偏好、习惯、默契都不是"文档"，检索不出来。

三、路线三：记忆系统——Agent 的海马体

给 Agent 一个会生长的记忆：

短期记忆：当前对话（上下文窗口）
中期记忆：任务摘要（"用户在重构支付模块，讨厌 ORM"）
长期记忆：跨任务知识（"用户对甲醛过敏"）

和 RAG 最大的区别：记忆系统不存原文，存提炼。对话结束，模型自己判断"什么值得记住"，写成结构化记忆，带置信度和来源。

检索也不同：RAG 按"向量相似度"（文本长得像不像），记忆按"任务相关性"（对当前任务有没有用）。后者需要理解任务，难一个数量级。 Mem0、Zep 在做这个；Anthropic 的 Agent Skills 也是记忆的一种形态——把经验沉淀成可复用的技能。

但路线三最有前景，也最难落地，三个坑每个都能埋掉一个团队：

第一，只存不忘。 90% 自研记忆系统的死因。信噪比随时间单调下降，三个月后库里几十万条，召回一半垃圾。遗忘不是缺陷，是功能——借鉴艾宾浩斯曲线：重要性随时间衰减，被"想起"就加强，从不被想起的自动沉底。

第二，记忆打架。 上月说"用 Python"，本月说"切 Go 了"，信哪个？需要版本号和冲突解决——最简单的：新覆盖旧，保留变更记录；更进一步：冲突时主动问用户确认，把"记忆的写权限"部分交还给用户。

第三，不可观测。 Agent 做了个奇怪决策，问为什么，答"根据我的记忆"——哪些记忆？什么时候写入？可信度多高？记忆的读写必须打日志，否则 debug 两眼一抹黑。再加一条红线：PII 过滤，密码身份证号写进记忆就是数据泄露；记忆分"用户可见"和"系统内部"两层，前者用户可查可删——不让用户看自己"被记住了什么"的记忆系统，走不远。

结语

选路线之前，先回答：你的 Agent 要"活"多久？一次性任务，超长上下文最省事；查资料，RAG 够用；只有当你希望 Agent"越来越懂用户"时，才需要记忆系统。

务实的演进是三步：先做记忆审计——80% 的团队会发现，要的只是"跨会话的几个关键字段"，KV 加规则就够，别为"记忆系统"四个字过度设计；再按"存活时长"选路线；最后，先设计遗忘，再设计记忆——一条记忆多久过期？冲突谁说了算？用户怎么删自己的记忆？

记忆系统的终极考验从来不是记住，而是忘掉。好的 Agent 像好的同事：记得关键的事，忘了细枝末节，而且你问它"为什么记得这个"，它能说出理由。
