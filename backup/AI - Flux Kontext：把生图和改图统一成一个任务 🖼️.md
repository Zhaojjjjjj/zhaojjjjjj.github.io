> Black Forest Labs 在 2025 年 6 月开源了 Flux.1 Kontext：一个"上下文感知"的图像生成/编辑模型。它的核心突破是把"生图"和"改图"统一成了一个任务。这篇讲讲这个统一是怎么做的。

## 改图的三种旧路线

在 Kontext 之前，图像编辑有三条路线，各有硬伤：

1. **Inpainting**（遮罩重绘）：只能改局部，改完和原图风格容易脱节。
2. **InstructPix2Pix**（指令编辑）："把猫变成狗"，但经常连背景一起改了——**保真度**是老大难。
3. **ControlNet**（条件控制）：保结构，但要额外训练适配器，流程重。

## Kontext 的统一：都变成"序列生成"

Kontext 的洞察：**生图和改图，本质都是"给定上下文，生成图像序列"**。

```
生图：[文本] → 图像
改图：[原图 + 文本指令] → 新图像
多轮改图：[原图 + 指令1 + 中间图 + 指令2] → 新图像
```

把原图也 token 化，拼进 Transformer 的输入序列，模型用**自注意力**同时看"原图"和"要生成的新图"。改图不再是"外部操作"，而是"带着记忆的生成"。

## 为什么保真度突然好了

关键在**联合注意力机制**：

- 传统方法：原图是"参考"，生成时管不住手。
- Kontext：原图的每个 patch 都在注意力矩阵里，新图的每个 patch 生成时都要"投票"参考原图对应位置。不该改的地方，注意力权重自然低。

实测效果：换衣服不换脸、改背景不改人、连续多轮编辑不崩——这三件事在 2025 年中之前，没有一个开源模型能同时做到。

## 开源的意义

Kontext 开源（非商业许可的变体也在路上了）意味着：

1. **Nano Banana 有了开源平替**：Gemini 的对话式修图出圈后，开发者终于有了能本地跑的方案。
2. **工作流可复现**：闭源 API 的编辑是黑盒，Kontext 让"改图"进入了可调试、可微调的范畴。
3. **电商/设计场景爆发**：模特换装、产品图改色、老照片修复——这些场景要的是"改得准"，不是"画得美"，Kontext 正好卡位。

## 一句话总结

Kontext 的贡献不是"又一个生图模型"，而是证明了**编辑可以是生成的特例**。当原图变成输入序列的一部分，"保真"就从外部约束变成了内生能力。这个思想会重塑所有条件生成任务。
