> 2026 年 9 月 8 日，美国 NSA/CISA/FBI 联合发布 AA26-251A 公告：点名 6 家中国 AI 企业，指控其"系统性、工业级"蒸馏美国前沿模型。但"蒸馏"是个技术动作——**技术上，到底能不能"鉴定"一个模型是蒸馏出来的？** 这篇只讲技术，不站队。

# 蒸馏风波：AA26-251A 的技术解读——"鉴定蒸馏"到底难在哪

## 公告在指控什么

```
"自 2024 年底起，系统性、工业级蒸馏 Claude、ChatGPT、Gemini、Grok"
```

翻译成技术语言，指控的是**黑盒蒸馏**：

```python
# 被指控的流程（示意）
for prompt in massive_prompt_set:          # 数百万个 prompt，覆盖全任务类型
    response = claude_api(prompt)          # 调美国模型的 API
    dataset.append((prompt, response))     # 收集"问题→答案"对
student.train(dataset)                     # 在自己的模型上训练
```

注意：这和"用 API 做产品"是同一个动作，区别只在**意图和规模**——而意图，恰恰是技术鉴定最难的部分。

# 一、能检测的三种信号

Anthropic 的配套报告提到"约 2 亿次交流"，阿里规模最大。技术上，鉴定蒸馏靠三种信号，强度递减：

**1. API 调用模式（最弱）**

```
正常用户：分散、昼夜节律、任务类型随机
疑似蒸馏：批量、覆盖全任务类型、7×24、无节假日
```

这是行为分析，不是证据。**调用量大可能是正常业务**（比如一个 AI 客服公司）——行为只能"起疑"，不能"定罪"。

**2. 输出指纹（中等）**

每个模型有独特的"文风"：特定 token 的偏好分布、句式习惯、甚至标点模式。学生在老师数据上训练，会**继承这种分布**——

```python
# 伪代码：指纹检测
teacher_dist = measure_token_distribution(claude_outputs)    # 老师的"文风向量"
student_dist = measure_token_distribution(suspect_outputs)   # 嫌疑模型的"文风向量"
similarity = cosine(teacher_dist, student_dist)
# similarity > 0.95，且排除了"同训练数据"的解释 → 高度可疑
```

但有个根本困难：**同分布不等于抄袭**。如果两家都用 Common Crawl 训，文风自然接近——"像"可能是"同源"，不一定是"师生"。

**3. 错误继承（最强）**

老师犯过的**独特错误**，学生也犯，且错误模式一致：

```
Claude 在某道冷门题上有一个独特的错误解法（全网只有它这么错）
嫌疑模型在同一道题上，用了同样的错误解法
→ 这不是"巧合"能解释的
```

这是 DNA 级别的证据——**错误不会"同源"，只会"遗传"**。但它要求鉴定方掌握"老师独有的错误清单"，而这本身就是非公开信息。

# 二、灰色地带：三条线

```
线一（白）：读公开论文复现 —— DeepSeek V3 的技术报告就是干这个的
线二（灰）：用 API 输出做 SFT —— 违反 ToS，但"学习"和"蒸馏"的边界模糊
线三（黑）：系统性爬取 + 商业竞争 —— AA26-251A 指控的
```

线二是最难的：**"向 Claude 学习写作技巧"和"蒸馏 Claude"，技术上是同一个动作**——都是"看输出、学模式"。区别只在规模和意图，而这两者都不在 loss 函数里。**ToS 禁止的是"行为"，不是"技术"**——这也是多位研究者质疑 AA26-251A"部分技术判断"的原因：把"行为问题"包装成"技术鉴定"，证据标准是存疑的。

# 三、DeepSeek 的阳谋：用 openness 自证

有意思的对照：被点名的 6 家里，DeepSeek 的技术报告是**最详细的**——FP8 训练细节、MLA 架构、GRPO 参数，全公开。

```
逻辑：报告越详细 → 复现路径越清晰 → "抄"的指控越难成立
     "我连怎么训的都告诉你了，还用得着抄吗？"
```

这是阳谋：**openness 是最好的不在场证明**。而报告里藏着的真正底气是——V4 的 1M 上下文、MoE 架构、长程 RL，这些都不是"调 API 能调出来"的。**蒸馏能抄"答案"，抄不走"训练基础设施"。**

# 结语

AA26-251A 的技术真相可以浓缩成一句话：

> **蒸馏的"行为"可观测，"意图"不可判定。API 日志能证明"你调了 2 亿次"，证明不了"你为什么调"——而"为什么"，恰恰是定罪的全部。**

技术、地缘、商业的三重奏里，技术只负责提供"嫌疑"，不负责"判决"。作为开发者，记住一条就够了：**用竞品 API 的输出训练竞品，违反 ToS——别碰。** 至于大厂的神仙打架，看的是戏，学的是"openness 是最好的辩护"。
