> 45 秒，3 秒。同一台机器，同一个 10 万模块的中型项目，Vite 7 打包 45 秒，Vite 8 只要 3 秒。**15 倍**。这不是优化，是换了引擎——Vite 8 把打包器从 JS 写的 Rollup，统一换成 Rust 写的 Rolldown。构建时间的数量级变化，会改变开发流程本身：45 秒你要去倒杯水，3 秒你还没切回浏览器包已经好了。

# Vite 8 + Rolldown：前端工具链"Rust 化"的最后一块拼图

Vite 8 不是孤例：

```
esbuild（Go）：2019，打包快 100 倍，第一个掀桌子
SWC（Rust）：  2020，编译快 20 倍，babel 掘墓人
Turbopack（Rust）：2022，Vercel 的新打包器
Rolldown（Rust）：2026，成为 Vite 8 默认打包器
Oxc（Rust）：   parser、linter 全家桶，重写工具链地基
```

趋势再清楚不过：**JS 写的工具，正在被系统语言重写**。Vite 8 是标志性事件——不是小众工具换引擎，是最主流的构建工具彻底换心脏，Rust 化从"极客尝鲜"进入"默认选项"。为什么是 Rust/Go？构建工具的瓶颈从来不在算法，在**并行和内存**——JS 单线程再优化也有天花板，系统语言榨干多核、精细控制内存。这不是语言鄙视链，是物理规律。

# 一、Rolldown 快在哪：并行、内存、没有中间商

**第一，并行：把多核吃满。** Rollup 模块解析、transform、打包基本串行；Rolldown 用 Rust 的 fearless concurrency 全管线并行，几千模块分散到所有核心，最后合并。10 万模块，串行和并行的差距就是 45 秒和 3 秒。**JS 单线程在 embarrassingly parallel 的场景里就是天花板。**

**第二，内存：少一个数量级。** 零拷贝加 arena 分配，大项目内存占用是 Rollup 的 1/10。内存少不只是省内存——GC 压力小、CPU 缓存命中高，速度跟着涨；CI 不用为打包加内存，省真金白银。以前 build 慢，一半怪 CPU 一半怪内存，Rolldown 把这一半顺手解决。

**第三，原生：没有中间商。** Rollup 跑在 Node 里：启动、JS 解析、worker IPC，每层都是税。Rolldown 是原生二进制，直接跑。**少一层中间商，少一层税。** 三件事单独看都不神秘，合在一起就是 15 倍——工程加速从来不是靠天才算法，靠把每层税都免掉。

# 二、Rolldown vs Turbopack：生态兼容 vs 架构重构

同样 Rust 打包器，走两条路：

```
Rolldown（Vite 8）：  通用打包器，刻意兼容 Rollup 插件 API
                      → 生态优先：几千现成插件直接用，最小迁移成本换最大用户基数
Turbopack（Next.js）：深度绑定 Next.js，为增量构建重新设计
                      → 架构优先：dev 体验极致，但先上它的船
```

对普通开发者，Rolldown 更友好：不换框架、不重写插件，升个版本号拿 15 倍。**这也是 Vite 8 成为"标志性事件"的原因——Rust 化的红利第一次落到"不折腾"的人手里。**

升级前查三件事：**插件兼容**——用过 Rollup 内部 API 或冷门 hook 字段的插件会挂，对着官方兼容表把 `vite-plugin-*` 过一遍（Vite 团队做了半年生态兼容，长尾还得自己验）；**Node 版本**——Vite 8 要 Node 20.19+/22.12+，先升 Node 再升 Vite；**产物 hash 会变**——Rolldown 和 Rollup 分包策略有细微差别，CDN 长期缓存策略的发版做一次全量刷新。大部分项目可无痛升级，但"大部分"不等于"你的"——先在非核心项目跑一遍。

# 三、真正的终局：Oxc，和"解析一次，处处复用"

Rolldown 只是冰山一角。同一时期，Oxc 正在把工具链地基整个重写：parser、linter、formatter、minifier，一套 Rust 实现。

```
以前：babel 解析一遍 → ESLint 再解析一遍 → 打包器再解析一遍
      同一份代码被解析三遍，三倍的税
Oxc 愿景：解析一次，AST 复用——lint、format、打包都吃同一份
```

**这才是 Rust 化真正的终局：不只是单个工具变快，而是工具之间不再重复交税。** Rolldown 和 Oxc 同一作者、同一套 AST——看 Vite 8 别只看"build 快了"，背后是一盘更大的棋：前端工具链正从"一堆 JS 小工具"进化成"一套 Rust 基础设施"。这次升级拿 15 倍，下次可能是 lint 快 10 倍，红利会一波一波来。

# 结语

Vite 8 改变的不只是数字：**更频繁的预览包**（3 秒丢个链接，评审节奏全变）、**更大的 monorepo 也敢了**（10 万模块 3 秒，拆包顾虑少大半）、**CI 合并队列变快**（前端 build 常是流水线最长环节）。但小项目感知不强——几百模块本来就 2 秒，这是给"大项目"和"大团队"的礼物。

还要记住：**瓶颈不会消失，只会转移**。build 3 秒了，`tsc` 还要 40 秒，测试还要 2 分钟——工具链每代加速，都会把下一层瓶颈顶到面前。瓶颈可见才有优化抓手，只是别指望换个打包器解决一切，它解决的是"打包"这一层，每一层都有自己的 Rolldown 时刻，还没到来。

回滚预案：升级前把旧 build 产物 tag 留一份，`package-lock.json` 的 diff 单独提交——回滚时 revert 这一个提交，干净利落。升级当天别叠加发功能，一个 MR 只做一件事。
