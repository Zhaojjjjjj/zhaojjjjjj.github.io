> Kimi K2.7 Code 高速版：同一个模型，提速 5-6 倍，180 token/s。模型权重一动没动，速度翻了 5 倍——**推理优化是 2026 年最被低估的"免费 scaling"**。

先建立正确的性能观。LLM 推理有两个阶段，瓶颈完全不同：

```
Prefill（处理输入）：compute-bound → 瓶颈在算力（FLOPS）
Decoding（逐 token 生成）：memory-bound → 瓶颈在显存带宽
```

**180 tok/s 是 decoding 的速度**，瓶颈是"每生成一个 token，要把整个 KV Cache 从显存搬到计算单元"。优化 decoding，就是和内存带宽较劲。下面五式，每一式都在砍"搬运量"或"等待时间"。

# 一、推测解码：小模型猜，大模型批改

```python
# Speculative Decoding 的循环
draft_tokens = small_model.generate(prompt, n=5)      # 小模型：快，猜 5 个
accepted, n = big_model.verify(prompt, draft_tokens)  # 大模型：并行验证，一次过
# 接受 4 个 → 这一步生成了 4 个 token，只花了"1 次大模型推理"的时间
```

核心洞察：**大模型验证 5 个 token 的时间 ≈ 生成 1 个 token 的时间**（因为验证是并行的）。只要小模型猜得准（接受率高），提速就是 3-4 倍。

接受率是关键：代码任务的接受率最高（语法高度结构化，小模型容易猜对），开放式写作最低。**K2.7 是 Code 高速版——选了接受率最高的场景**，这是产品层面的聪明。

# 二、PagedAttention：把显存碎片清零

vLLM 的 PagedAttention 把 KV Cache 按块管理，像操作系统的虚拟内存：

```
传统：每个请求的 KV 连续分配 → 碎片 → batch 开不大
Paged：KV 按 block 分配，按需映射 → 碎片 ≈ 0 → batch 开大 3 倍
```

注意：**这提的是吞吐，不是延迟**。batch 大了 3 倍，每个人还是 30 tok/s，但同时服务的人多 3 倍。个人用的"高速版"和 serving 的"高吞吐版"，优化的是两个指标——**别混为一谈**。

# 三、量化：精度换速度，但要选对场景

```
FP16 → FP8：速度 ×1.5，精度损失 <1%
FP8 → INT4：速度 ×2，精度损失 2-3%
```

K2.7 高速版用 FP8，不是 INT4。为什么？**编程任务对精度敏感**——INT4 的 2-3% 精度损失，在数学上是"小数点后两位"，在代码上是"多一个 bug"。**量化的选型，取决于"精度损失的代价"**：聊天任务用 INT4 没事，代码任务老老实实 FP8。

# 四、CUDA Graph + EAGLE：干掉调度开销

```
普通：每次推理都要 CPU 调度 GPU（kernel launch 开销）
CUDA Graph：把计算图"录"下来，一次发射 → 小 batch 延迟降 30%
```

EAGLE（2026 年的新贵）：在 hidden states 上做预测，而不是 token 上——**接受率比推测解码更高**，因为 hidden states 的信息密度更大。提速 2-3 倍，而且和推测解码可以叠加。

# 五、组合：没有银弹，只有乘法

```
推测解码（3x）× FP8（1.5x）× CUDA Graph（1.3x）≈ 5.8x
30 tok/s × 5.8 ≈ 174 tok/s，约等于 180 tok/s
```

**每个优化 1.3-3 倍，乘起来就是 5-6 倍。** K2.7 的 180 tok/s 不是某一个黑科技，是五个 1.x 的乘积。这就是推理优化的真相：**没有银弹，只有组合**——而组合的前提，是你分得清瓶颈在 compute 还是 memory。

# 结语

给开发者的三条：

1. **先优化，再换模型**：模型不变，速度翻 5 倍——抱怨模型慢之前，先问"框架榨干了吗"；
2. **升级框架 = 免费提速**：这些优化都在 vLLM/SGLang 里，升个级就行；
3. **分清延迟和吞吐**：个人用要延迟（推测解码），serving 要吞吐（PagedAttention）——优化目标不同，手段不同。

> **2026 年，模型的竞争一半在训练，一半在推理——而推理优化，是不花钱的 scaling。**
