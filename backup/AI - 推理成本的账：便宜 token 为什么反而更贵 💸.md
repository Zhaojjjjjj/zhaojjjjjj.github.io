> 模型价格战打了一年，token 单价降了 90%。但很多团队的账单反而涨了——因为便宜的 token 诱使你调用更多、想得更久。这篇算算推理成本的真实构成。

## 单价降了，用量涨了

这是 AI 版的杰文斯悖论：**效率提升不会减少消耗，只会扩大使用**。

```
单价降 90% × 调用量涨 20 倍 = 总账单涨一倍
```

只比单价，是 2024 年的思维。2026 年要比的，是**完成一个任务的期望成本**。

## 三个隐形成本

### 1. 思考税（reasoning tax）

推理模型为了答一道题，可能在内部"想" 10 倍长度的 thinking token，而用户只看到 1 倍的答案。在按输出 token 计费的定价下，**thinking token 才是账单的大头**。

```
用户看到：200 token 的答案
实际消耗：2000 token 的思考 + 200 token 的答案
账单：按 2200 个输出 token 算
```

**对策**：按任务难度路由——简单任务用非思考模型，难题才上推理模型。（呼应之前写的混合推理架构）

### 2. 重试税

弱模型单价便宜，但一次成功率 70%；强模型贵 3 倍，一次成功率 95%。

```
弱模型期望成本 = 单价 × (1/0.7) ≈ 单价 × 1.43  （还要算重试的延迟）
强模型期望成本 = 单价×3 × (1/0.95) ≈ 单价 × 3.16
```

看着弱模型赢？别急——**重试还有延迟成本和用户体验成本**。对实时性要求高的场景，一次失败的用户流失，远比 token 贵。

**对策**：给每个任务设"一次成功率"指标，和单价一起看。

### 3. 上下文税

长上下文的 input token 看似便宜，但 attention 计算是平方级增长：

- 128K 上下文：首 token 延迟可能是 4K 上下文的 10 倍+
- 你塞进去的"以防万一"的文档，每次都在交税

**对策**：prompt caching（之前专门写过一篇）、上下文压缩、该 RAG 的别硬塞。

## 算账公式

```
期望成本 = 单价 × (1 + 思考倍数) × (1 / 一次成功率) × (1 - 缓存命中率 × 缓存折扣)
```

不用精确算，记住三个杠杆就行：

1. **路由**：按难度选模型，别拿牛刀杀鸡，也别拿杀鸡刀砍牛；
2. **缓存**：重复的 system prompt 和文档，该缓存缓存；
3. **一次做对**：在关键链路上用强模型，比"便宜模型+重试"更省。

## 一句话总结

推理成本公式：**期望成本 = 单价 × 思考倍数 ÷ 一次成功率**。降本三板斧：**按难度路由、缓存复用、减少重试**。记住：**最贵的不是 token，是失败的那一次调用**。
