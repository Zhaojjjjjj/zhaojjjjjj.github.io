某团队去年把主力模型换成便宜 70% 的新模型，三个月后财务找到他们：AI 账单涨了 40%。

这不是个例。模型价格战打了一年，token 单价降了 90%，但很多团队的总账单不降反升。因为**便宜的 token 诱使你调用更多、想得更久**——这是 AI 版的杰文斯悖论：效率提升不会减少消耗，只会扩大使用。

## 先看清账单的构成

```
月账单 = Σ(每次调用 [输入 token × 输入单价 + 输出 token × 输出单价])
```

输出单价通常是输入的 2-4 倍。而"输出"里的大头，往往不是答案，而是**思考过程**。

```
用户看到的答案：           200 token
模型内部的思考：         2,000 token
账单按输出计费：         2,200 token × 输出单价
```

只比单价，是 2024 年的思维。2026 年要比的，是**完成一个任务的期望成本**。下面三个隐形成本，每个都可能比单价差异大一个数量级。

## 隐形成本一：思考税

推理模型有个特点：**想得越久，答得越好，但账单越贵**。不同任务的"思考/答案比"天差地别：

| 任务类型 | 思考 token | 答案 token | 倍数 |
|---|---|---|---|
| 简单问答、分类 | ~100 | ~100 | 1x |
| 代码生成 | ~2,000 | ~500 | 4x |
| 数学证明、复杂规划 | ~10,000 | ~800 | 12x |

12 倍意味着：你在为 12 份"草稿纸"付费，只为了 1 份"答卷"。

**对策是按难度路由**，而不是一刀切：

```
用户问题 → 难度分类器（小模型，几乎免费）
  ├─ 简单 → 非思考模型（快 5 倍，便宜 10 倍）
  ├─ 中等 → 思考模型，限制思考预算
  └─ 困难 → 最强推理模型，放开思考
```

分类器本身的成本忽略不计，但能把 70% 的简单请求从"思考税"里摘出来。这正是混合推理架构在工程上的落地。

## 隐形成本二：重试税

弱模型单价便宜，但一次成功率 70%；强模型贵 3 倍，一次成功率 95%。算期望成本：

```
弱模型期望成本 = 1.0 × (1/0.70) ≈ 1.43   （平均要调 1.43 次）
强模型期望成本 = 3.0 × (1/0.95) ≈ 3.16
```

看着弱模型赢了？别急着下结论。重试还有两笔账：

**延迟成本**：每次重试都是一次完整的往返。在实时交互场景（客服、结账助手），多一次重试就是多 3-5 秒等待。用户流失的代价，远比 token 贵。

**级联成本**：在 Agent 链路里，一步失败会导致整个链条重跑。一个 5 步的 Agent，每步成功率 90%，整体成功率只有 59%。这时候**每一步都值得用强模型**——短板效应下，最弱的那步决定了总成本。

**对策**：给每个任务设"一次成功率"指标，和单价一起看。核心链路用强模型保成功率，边缘任务用弱模型省单价。

## 隐形成本三：上下文税

长上下文的 input token 看似便宜，但有两个隐藏代价：

**计算代价**：attention 是平方级复杂度。128K 上下文的首 token 延迟，可能是 4K 上下文的 10 倍以上。你为"以防万一"塞进去的文档，每次调用都在交税——交的不是 token，是延迟。

**注意力稀释**：上下文越长，模型越容易忽略关键信息（大海捞针问题）。你塞了 100 页文档，模型可能恰恰没看到第 37 页的那行关键配置。

**对策**：
- 该 RAG 的别硬塞：检索出 top_k 再拼，比全量塞便宜又准；
- prompt caching：重复的 system prompt 和文档只算一次钱（之前专门写过一篇）；
- 定期做"上下文审计"：看看 prompt 里有多少 token 是从来没被模型"注意"过的。

## 一个完整的算例

客服问答场景，日均 1 万次会话，两种方案：

```
方案 A：单一强模型
  单价：输入 ¥0.01/K，输出 ¥0.04/K
  平均输入 2K（含 1.5K 缓存），平均输出 0.5K（含思考）
  单次成本 ≈ 0.5×0.01 + 1.5×0.01×0.1 + 0.5×0.04 ≈ ¥0.0265
  一次成功率 95% → 期望成本 ¥0.0279/次
  月成本：10,000 × 30 × 0.0279 ≈ ¥8,370

方案 B：路由 + 缓存 + 弱模型打底
  70% 简单问题走弱模型（¥0.002/K），30% 走强模型
  单次期望成本 ≈ ¥0.012
  一次成功率 92% → 期望成本 ¥0.013/次
  月成本 ≈ ¥3,900
```

**差了一倍多**。而单价差异只有 3-5 倍——真正的差距来自路由和缓存的乘数效应。

## 降本检查清单

下次review AI 账单时，按这个顺序查：

1. **路由**：有没有按难度分流？多少简单请求在烧思考模型的钱？
2. **缓存**：system prompt 和静态文档的缓存命中率是多少？低于 80% 就是漏水；
3. **重试率**：整体重试率超过 10%？先提成功率，再谈单价；
4. **上下文**：平均输入 token 是不是在悄悄变长？设个告警线；
5. **影子测试**：新模型上线前，先切 5% 流量对比"任务完成成本"，别只看单价。

最后说个反直觉的结论：**2026 年最省钱的策略，往往不是用最便宜的模型，而是让最贵的模型少干活**——把 70% 的请求挡在它前面，剩下的 30% 让它一次做对。省钱的本质是减少浪费，不是压低单价。
