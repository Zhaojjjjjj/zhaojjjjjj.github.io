> 1M token 上下文已经不稀奇了，但"能装下"不等于"记得住"。2026 年初，行业意识到：长上下文之后，真正的战场是**记忆架构**。这篇聊聊三种路线。

## 路线一：超长上下文（ brute force）

```
把所有东西都塞进 prompt：文档、历史对话、工具结果
模型：1M tokens，我全看
```

**优点**：简单，无外部依赖。
**缺点**：

1. **贵**：1M tokens 的输入，$2-5 一次。
2. **注意力稀释**："大海捞针"测试证明，信息在中间位置时，模型经常"看不见"。
3. **遗忘**：上下文窗口是 FIFO 的，新信息进来，旧的被挤掉——没有"重要性"概念。

## 路线二：RAG（外挂硬盘）

```
问题 → 向量检索 → 找最相关的 10 个片段 → 塞进 prompt
```

**优点**：知识可更新，不用重训模型。
**缺点**：

1. **检索质量是天花板**：embedding 搜不到，模型再强也没用。
2. **碎片化**：10 个片段是散的，模型要自己拼——跨文档推理经常断。
3. **没有"理解"**：RAG 是"查资料"，不是"学习"。下次问同样的问题，还得再查一遍。

## 路线三：记忆系统（Agent 的海马体）

2026 年的新贵：给 Agent 一个**会生长的记忆**。

```
短期记忆：当前对话（上下文窗口）
中期记忆：任务相关的摘要（"用户在装修，预算 20 万，喜欢原木风"）
长期记忆：跨任务的知识（"用户对甲醛过敏"、"上次推荐的方案他否了"）
```

关键技术：

1. **记忆写入**：对话结束，模型自己提炼"值得记住的"，写进记忆库。
2. **记忆检索**：新任务时，按相关性召回——不是向量相似，是"任务相关"。
3. **记忆遗忘**：过时的记忆要删（"用户已经搬家了，旧地址作废"）。

Mem0、Zep 等框架在做的就是这个。Anthropic 的 Agent Skills（2026 年 10 月）也是记忆的一种形态——**把经验沉淀成可复用的技能**。

## 三条路线的对比

|  | 长上下文 | RAG | 记忆系统 |
|---|---|---|---|
| 本质 | 全记住 | 现查 | 学会记住 |
| 成本 | 极高 | 低 | 中 |
| 跨任务 | ❌ | ❌ | ✅ |
| 成熟度 | 高 | 高 | 早期 |

## 一句话总结

2026 年的共识：**上下文是"工作内存"，记忆是"长期存储"**。只靠长上下文，就像只用内存不用硬盘——能跑，但贵且笨。Agent 的下一跳，是学会"记住"。而"记住什么、忘掉什么"，是比"装下多少"更难的问题。
