> GPT-5.1 发布于 2025 年 11 月 12 日，核心升级是"自适应推理"：模型自己判断问题难度，动态决定思考深度。这篇聊聊"让模型自己决定想多深"在技术上意味着什么。

## 从手动挡到自动挡

之前（Claude 的 thinking budget）：

```python
# 开发者手动指定
response = client.messages.create(
    model="claude-4",
    thinking={"type": "enabled", "budget_tokens": 10000}  # 手动挡
)
```

GPT-5.1 之后：

```python
# 模型自己决定
response = client.chat.completions.create(model="gpt-5.1")
# 内部：简单问题 0 tokens 思考，数学证明 20K tokens
```

**决策权从开发者转移到了模型**。这是"混合推理"的终极形态。

## 怎么做到的：难度估计器

核心是一个轻量的**难度分类器**，跑在主模型之前：

```
输入 query → 分类器 → {简单: 0.8, 中等: 0.15, 困难: 0.05}
→ 按期望分配 thinking budget
```

训练这个分类器需要**难度标注数据**：什么样的 query 需要多深的思考。OpenAI 的做法是用大模型在验证集上"试"——同样的问题，给 1K 和 10K budget，看答案质量差多少。差得多=难，差得少=简单。

## 和 Claude 路线的对比

|  | Claude（手动 budget） | GPT-5.1（自适应） |
|---|---|---|
| 控制权 | 开发者 | 模型 |
| 可预测性 | 高（花多少钱心里有数） | 低（账单看天） |
| 易用性 | 低（要调参） | 高（无脑用） |
| 翻车 | 预算设小了答错 | 模型误判难度 |

2025 年底的行业分成了两派：**控制派**（Anthropic：开发者要掌控成本）和**智能派**（OpenAI：模型比你更懂）。没有对错，是 trade-off。

## 工程实践

1. **监控实际 budget**：API 返回里看 `reasoning_tokens`，建立"问题类型→实际消耗"的基线。
2. **设置上限**：自适应不等于无上限，`max_reasoning_tokens` 永远要设。
3. **AB 测试**：同一批任务，对比"自适应" vs "固定 budget"的成本和质量——很多场景下，固定 budget + 规则分级更便宜。

## 一句话总结

自适应推理是"把超参还给模型"。它赌的是：模型对难度的判断，比开发者的经验更准。这个赌注在 80% 的场景下是对的，剩下 20%——记得设上限。
