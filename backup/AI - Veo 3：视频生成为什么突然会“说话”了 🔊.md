> Google I/O 2025 上，Veo 3 演示里人物开口说话的那一刻，全场起立。在此之前，AI 视频是"默片"——画面再精美，也得后期配音。Veo 3 第一个做到了原生音画同步。这篇讲讲它是怎么做到的。

## 难点在哪

视频生成（diffusion）和音频生成，之前是两条完全独立的技术线：

- **视频**：DiT（Diffusion Transformer）在 latent 空间去噪，时间维度靠 3D 注意力。
- **音频**：声码器 / 音频 diffusion，采样率 24kHz，一秒就是 24000 个点。

硬拼接的方案（先生成视频，再用另一个模型配音）有两个死结：**口型对不上**，**音画语义脱节**（画面是雨声，配出来是鸟叫）。

## Veo 3 的路线：联合建模

核心思想：**让同一个 Transformer 同时理解"画面"和"声音"是同一件事的不同表现**。

技术上：

1. **统一 token 流**：视频帧 patch 和音频 token 拼进同一个序列，cross-attention 让它们互相"看见"。
2. **对齐的位置编码**：时间轴是共享的——第 2.3 秒的画面 token 和第 2.3 秒的音频 token，在位置编码上就是邻居。口型同步不是"学出来"的，是架构上"注定"的。
3. **联合去噪**：diffusion 过程同时对视频 latent 和音频 latent 去噪，噪声调度（noise schedule）跨模态协调。

## 为什么之前做不到

- **数据**：需要海量"音画严格对齐"的高质量视频。YouTube 给了 Google 别人没有的数据护城河。
- **算力**：联合建模的序列长度爆炸（视频 token + 音频 token），训练成本是纯视频模型的数倍。
- **评估**：音画同步没有好的自动化指标，只能靠人看——迭代飞轮转得慢。

## 对开发者的意义

1. **多模态不是"多模型"**：Veo 3 证明，真正的多模态是联合建模，不是 pipeline 拼接。这个结论会外溢到所有模态组合。
2. **数据护城河 > 算法**：音画对齐数据的稀缺性，决定了这条赛道只有巨头能玩。
3. **应用范式变了**：从"生成默片再配音"到"一句话生成有声短片"，短视频生产的成本结构被重写。

## 一句话总结

Veo 3 的"说话"不是加了个配音模块，而是把声音和画面放进同一个 Transformer 里一起"想"。AI 视频的默片时代结束了——而终结它的不是更好的视频模型，是更好的"对齐"思想。
