同一周，你可能在手机上刷到过两段 AI 生成的视频：一段行云流水，人物走过集市，衣摆和光影都挑不出毛病，弹幕一片惊叹；另一段里，主角走着走着，腿突然多了一条。

前者来自闭源模型的 demo，后者来自某个开源模型。而在今年夏天，这种"一个天上、一个地下"的差距，第一次被认真挑战了——开源视频生成，终于有了一个"能用"的基座。

## 为什么开源视频这么难

视频生成的门槛有三道，每道都要命：

**第一道：数据。** 图片有几十亿级的图文对数据集，视频呢？需要的是"高质量视频 + 准确描述它在动什么"的文本。视频的清洗贵一个数量级：去水印、去黑边、切镜头、打标签、写 caption——每一帧都要处理。更要命的是**时序对齐**：caption 必须描述"变化"，而不是"画面"。静态描述（"一只猫坐在沙发上"）对视频模型几乎没用，它需要的是（"猫从沙发上跳下来，跑向门口"）。描述"动"，比描述"静"难一个数量级。

**第二道：算力。** 视频是"时间的平方"。一个十几帧的 720p 视频，token 量是单张图的几十倍。Diffusion 模型还要在这个 token 序列上跑几十步去噪——训练一个能用的视频模型，起步就是千卡月级别的投入。这不是"调调超参"的问题，是"有没有矿"的问题。

**第三道：评估。** 图像好坏一眼能看出来，视频要看"动得对不对"：动作合理吗？前后帧一致吗？物理规律违背了吗？没有好的自动化指标，只能靠人眼一帧帧看。这意味着**迭代飞轮转得极慢**——你甚至不知道这次训练到底变好了没有，只能凭感觉。

所以在今年中之前，开源视频模型的现状是：要么只能动 2 秒，要么画质糊成马赛克，要么动作诡异到像恐怖片。开篇那个"多一条腿"的视频，不是段子，是常态。

评估难，还带来一个连锁反应：**RLHF 在视频上很难做**。图像/文本的 RLHF 靠人标"哪个好"，视频要人看完几秒再判断，标注成本贵 10 倍，噪声还大。所以视频模型的对齐，主要靠"数据筛选前置"——把烂视频挡在训练集外面，而不是事后对齐。这也是数据加工线比模型结构更重要的原因之一。

## DiT：视频生成的标准答案

今天主流的视频生成，走的都是同一条路线：**Diffusion + Transformer（DiT）**。

思路其实很优雅：先把视频压缩成 latent（隐空间），然后让 Transformer 在 latent 上做去噪。图像的 DiT 已经验证了这条路，视频只是在此基础上多了一个维度——时间。

关键的分歧在**时序建模**怎么做，目前有三派：

1. **3D 注意力**：把时空当成一个整体做 attention。效果最好，但计算量随帧数平方增长——16 帧就是 256 倍的注意力矩阵，贵到离谱；
2. **分离式时空注意力**：先做空间注意力（帧内），再做时间注意力（帧间）。计算量友好，是目前的主流折中；
3. **因果时序建模**：只让当前帧看过去的帧，适合做视频续写、实时生成，对"未来"没有依赖。

Wan 系列走的是 DiT 路线，但真正的成本杀手不在 Transformer，在它前面的那一步。

## 3D VAE：第一成本杀手

视频进 DiT 之前，要先过 VAE 压缩。图像 VAE 只压空间，视频的 **3D VAE 要做时空联合压缩**：十几帧 720p 的视频，压完可能只剩几千个 latent token。

这个压缩比直接决定后面 DiT 的计算量——**VAE 压得好，DiT 的账单直接砍半**。但压缩比和重建质量是一对 trade-off：压得太狠，细节糊了，去噪模型再强也救不回来；压得太松，DiT 的 token 序列爆炸，训练成本上天。

所以视频模型的竞争，很大程度上是 VAE 的竞争。谁的 3D VAE 在"高压缩比"和"高保真"之间找到更好的平衡点，谁的模型就更便宜、更快、更清晰。这一步做好了，后面全是收益；做不好，后面全是补救。

## Wan2.2 的几个关键选择

在标准路线之上，Wan2.2 做了几个值得深挖的取舍：

**第一，课程学习：先 T2V，再 I2V。** 先训文生视频（T2V），让模型学会"怎么动"；再训图生视频（I2V），在 T2V 的基础上学"按着给定的图动"。这比一步到位训 I2V 稳定得多——**先学生成，再学约束**，是课程学习（curriculum learning）在生成模型里的经典应用。顺序反过来，模型容易顾此失彼。

**第二，DiT 里的 MoE：高噪声专家和低噪声专家分工。** 这是 Wan2.2 相对上一代最有意思的变化。Diffusion 的去噪过程里，早期的高噪声步和后期的低噪声步，干的完全是两件事：前者在定"大局"（构图、动作轨迹），后者在抠"细节"（纹理、光影）。用同一组参数干这两件事是浪费——Wan2.2 让不同的专家分别负责高噪声和低噪声阶段。**把 MoE 的"分工"思想从 LLM 搬到了 diffusion 的时间轴上**，这是个漂亮的跨界，也解释了为什么它的画面细节和动作连贯性能同时提升。

**第三，数据飞轮。** 阿里有文娱业务的数据资产——这是别人学不来的护城河。但比"有数据"更重要的是"数据的加工线"：镜头的切分、运动的标注、美学的过滤。开源社区可以复现架构，复现不了这条数据加工线。**开源的从来不只是权重，还有权重背后的数据工程**——只是后者没法开源。

在 DiT 之前，还有一派"运动模块"路线（AnimateDiff 那套）：冻结图像模型，只训一个时间模块。便宜，但天花板低——时间模块再强，也补不上"模型没见过运动"的短板。DiT 是"从头学生成视频"，贵，但天花板高。Wan2.2 选 DiT，等于宣告：**视频生成没有捷径，该交的学费一分不能少**。

## 容易被忽略的两块：文本编码器与推理加速

**文本编码器**：视频 prompt 里的"让猫跳起来"，靠文本编码器理解。Wan 系列用的是 UMT5 这类大编码器——视频的文本理解比图像难，因为 prompt 里全是"动作"和"变化"。编码器太弱，你写"缓慢推镜"，模型给你"快速摇镜"，动作语义对不齐。**视频生成的 prompt 工程，一半是编码器的功劳**，另一半才是 diffusion 本身。

**推理加速**：Diffusion 要跑几十步去噪，视频的每一步都比图像贵几十倍。业界的解法是蒸馏：LCM（Latent Consistency Model）把几十步压到 4-8 步，对抗蒸馏再往下压。画质损失一点，速度提升一个数量级。开源生态里，ComfyUI 的工作流 + 蒸馏模型，是普通人"玩得起"视频生成的关键——**原生的 50 步去噪，电费都付不起**。

## 能用来干嘛，以及还差多远

Wan2.2 开源后，实际可用的场景已经很具体：

- **短视频素材**：2-4 秒的转场、背景、空镜，质量够用；
- **电商**：产品图转动态展示，I2V 模式天然匹配这个需求；
- **研究**：第一个能复现、能微调的视频基座——学术界终于有东西可以动手改了，而不是只能对着闭源 API 做 prompt 工程。

但也要诚实：别指望它替代闭源模型。**时长、一致性、美学**，三项都还差一档。开源视频和闭源的差距，大概就是当年开源 LLM 和 GPT-4 的差距——能用，但还没追上。

差距在哪？不在架构——DiT + 3D VAE 这条路大家都走通了。差距在**数据飞轮和算力飞轮**：闭源模型用更多的视频数据、更大的训练量、更快的人评迭代，把同一套架构推到了更高的位置。这是资源差距，不是智力差距。好消息是，资源差距是可以用时间抹平的，智力差距不行。

## 开源生态：基座之后是什么

Wan2.2 开源的真正威力不在权重，在生态位：

- **ComfyUI 工作流**：节点化的工作流让视频生成变成"搭积木"，转场、垫图、重绘都有现成节点，不用写代码就能拼出一条视频管线；
- **微调**：DreamBooth 那套打法搬到视频上——几十段某个人、某种风格的视频，就能定制一个专属模型；
- **I2V 的平民场景**：电商产品图转动态、老照片动起来、PPT 转视频——这些场景不需要电影级的质量，"能用"就够了，而"能用"恰恰是开源基座最先满足的。

当年 Stable Diffusion 爆发，靠的也是这套组合：基座 + 微调 + 工作流。视频正在复刻这条路，只是慢了两年。慢两年的原因是算力门槛——图像的微调一张 3090 能玩，视频的微调现在还是"有点贵"。但门槛每年都在降。

## 我的判断

Wan2.2 的意义不在"多强"，在"有"。开源视频模型从"不能用"到"能用"，是 0 到 1 的突破。

我的判断是：**视频生成的 Stable Diffusion 时刻还没到，但倒计时已经开始了**。当年 SD 的爆发，靠的是"一个能用的开源基座 + 社区的数据和微调生态"。Wan2.2 扮演的正是"基座"这个角色——接下来的问题不是"架构行不行"，而是"社区能不能把数据和微调生态补上"。

如果历史押韵，闭源和开源的视频差距，会比当年 LLM 的差距收敛得更快。因为这一次，开源社区手里已经有了一张完整的路线图，缺的只是沿着它走下去的时间和算力。

押注开源视频，本质上是在押注"算力平权"的速度。训练成本每年都在降，蒸馏、量化、更高效的 VAE，每一项都在把门槛往下拽。当"训一个能用的视频模型"从千卡月降到百卡月，开源社区的数据飞轮就会转起来——而飞轮一旦转起来，闭源的领先优势会被快速侵蚀。LLM 的历史已经演过一遍了。
