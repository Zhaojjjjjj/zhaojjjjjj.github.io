> 万亿参数到 iPhone：中间隔着三个数量级。三级跳——蒸馏、量化、NPU，每一级都在回答"丢什么、留什么"。

先看目标：iPhone 的内存是 8GB，可用于模型的预算约 3GB。一个数万亿参数的模型（FP16 下几十 TB），要塞进 3GB，**压缩比是 10000:1**。这不是"优化"，是"重构"——每一级跳跃都在丢东西，关键是知道丢什么、不丢什么。

# 一、第一跳：蒸馏——从万亿到百亿

```
Gemini（云端，数万亿参数）
  → 蒸馏 → 10B 级学生模型
```

蒸馏的原理见之前的文章，核心是**用老师的"软标签"训练学生**，保留 90% 的能力，参数砍 99%。但端侧蒸馏有一个特殊要求：**学生必须为"手机任务"而蒸馏**，不是通用能力。

```
云端 Gemini：什么都会（写诗、解数学、聊哲学）
端侧学生：只学"手机上会用到的"——设闹钟、回短信、查日程、识图
```

**任务裁剪是第一跳的关键**：你不需要一个"小号的万能模型"，你需要一个"专精的手机助手"。能力范围缩小 10 倍，蒸馏的难度下降一个数量级。这就是为什么苹果敢做——**Siri 的任务边界是清晰的**。

# 二、第二跳：量化——从百亿到 3GB

```
10B 模型，FP16：20GB
  → 4bit 量化：5GB
  → 剪枝 + 蒸馏补偿：3GB
```

4bit 量化把每个参数从 16 位压到 4 位，精度损失 2-3%。但这里有个细节：**量化对"小模型"的伤害比大模型大**——大模型有冗余，小模型没有。所以端侧量化的标准动作是"量化感知训练"（QAT）：**训练时就模拟量化**，让模型提前适应低精度，而不是训完再硬压。

3GB 塞进 8GB 内存，还剩 5GB 给系统和 App——**刚好，但没有余量**。这意味着端侧模型不能"常驻满血"，必须做**按需加载**：Siri 唤醒时加载，不用时卸载。加载的 300ms，就是你说"Hey Siri"之后的那一下停顿。

# 三、第三跳：NPU——从"能跑"到"够快"

```
CPU 跑 4bit 模型：3 tok/s（不能用）
Apple Neural Engine：20+ tok/s（够用）
```

**NPU 不是"加速"，是"及格线"**。没有 NPU，端侧大模型就是个摆设。Apple Neural Engine 的算子专门为 transformer 优化（matmul、softmax、量化算子），**20 tok/s 是"刚好跟上人类阅读速度"**——再慢，用户就觉得卡了。

但 NPU 有**功耗墙**：全速跑，手机变暖手宝，电池 2 小时见底。所以端侧推理的真实策略是"**间歇爆发**"：Siri 回答时全速跑 2 秒，然后休眠。**端侧模型的性能指标不是"持续吞吐"，是"2 秒内的爆发延迟"**——这和云端完全是两个优化目标。

# 四、三面墙：内存、发热、更新

即使三级跳完成，还有三面墙：

**内存墙**：3GB 模型 + 系统 + App，8GB 很紧张。iOS 的内存压缩（memory compression）能挤一点，但**多任务一切回来，模型就被杀了**——下次唤醒重新加载，又是 300ms。

**发热墙**：NPU 全速跑的功耗，决定了"一天能问几次"。**端侧 AI 的上限不是算力，是电池。**

**更新墙**：模型更新要跟 iOS 版本走，云端一天一更，端侧一年一更。**端侧模型注定"过时"**——它的知识截止永远比云端早。

# 结语

端侧大模型的完整图景是：

> **蒸馏定"学什么"（任务裁剪），量化定"多小"（3GB 上限），NPU 定"多快"（20 tok/s 及格线）——而内存、发热、更新三面墙，定了它的天花板。**

苹果的策略从来不是"端侧替代云端"，而是**分级路由**：快的、隐私的、离线的放端侧；难的、重的、要最新的放云端。2026 年手机厂商的竞争从"摄像头"转向"NPU 跑分"，但真正的胜负手不在跑分，在**路由策略**——什么任务走端侧、什么走云端，这个分界线画在哪，决定了用户体验。而这条线，每个厂商画得都不一样。
