> 推理模型有个反常识的毛病：它不会"想太多"，它只是不知道什么叫"够了"。o3 级别的模型回答"1+1 等于几"也要在内部转几千个 token——不是它笨，是它的训练目标里从来没有"省着点想"这一项。这篇聊聊推理模型的效率困境：过度思考从哪来，贵在哪，以及工程上怎么治。

## 一个反常识的结论：思考不是越多越好

o1 范式给行业立了一个"公理"：测试时算力（test-time compute）越多，答案越好。Scaling law 在预训练上 work，在推理时似乎也 work——于是整个 2025 年上半年，所有旗舰模型都在加码思考长度。o3、Claude 的 extended thinking、Gemini 的 deep think，一个比一个能想。

但有个数字很少有人提：**在简单任务上，思考 token 超过某个点之后，准确率几乎不再涨，成本却线性涨**。内部评测里反复出现这样的曲线——数学竞赛题，多想 10 倍 token 能多拿 5 分；客服分类任务，多想 10 倍 token，准确率纹丝不动，账单翻 16 倍。

这不是"模型太强"的凡尔赛，这是训练目标错位：**RL 奖励"答对"，但从不惩罚"想太多"**。模型学到的最优策略是"往死里想，反正想多了不扣分"。人类考生都知道"这道选择题不值得花 10 分钟"，模型没有这根弦——它的"想"和"答"是同一个自回归过程，没有前置的难度判断模块。

## 过度思考到底长什么样

先给个可观测的定义。一次调用里，记思考 token 为 T，答案 token 为 A，定义**思考/答案比 R = T/A**：

| 任务类型 | 典型 R | 思考是否值钱 |
|---|---|---|
| 闲聊、寒暄 | 20~50 | 几乎纯浪费 |
| 分类、抽取、简单问答 | 10~30 | 基本浪费 |
| 代码生成 | 3~8 | 部分值钱 |
| 数学证明、复杂规划 | 8~15 | 值钱 |

**R > 10 且任务简单，就是过度思考。** 注意这个比值和模型能力无关——o3-pro 在"把这段话翻译成英文"上烧掉几千 token，和它在 IMO 难题上烧掉几万 token，用的是同一套"不知道停"的机制。

更隐蔽的一种过度思考是**"验证循环"**：模型得出答案后，不放心，又从头验证一遍，再验证一遍。思考轨迹里出现"让我再检查一遍……嗯，确实是 2"这种句式，就是典型的验证循环。人类做数学题会"验算"，但人类验算一道口算题只花 3 秒；模型没有"3 秒"这个概念，它的每次验证都是一次全量前向。

## 思考的边际收益曲线：多想≠多对

把"思考 token 量"画成横轴、"任务准确率"画成纵轴，不同任务是三条完全不同的曲线：

- **简单任务（分类、抽取、FAQ）**：曲线在 500 token 处就见顶，之后是平的。继续加思考，准确率不动，方差甚至变大——想太多会把自己绕晕，"过度思考导致答错"的 case 真实存在。
- **中等任务（代码生成、文档问答）**：曲线在 2000~5000 token 区间还有斜率，之后趋平。这里是"预算查表"最有价值的地方：给 8000 和给 3000，结果差不多，成本差 2.6 倍。
- **难题（竞赛数学、多步规划）**：曲线斜率维持到上万 token。这是推理模型真正的主场，也是唯一"思考税"交得值的地方。

关键洞察是**任务难度的分布是长尾的**：生产流量里 80% 是前两类，只有 20% 是第三类。而默认的"无差别深度思考"，等于用第三类的预算去跑第一类的任务。**效率优化的本质，不是"让模型少想"，是"让思考预算匹配任务难度"**——这句话听起来像废话，但 2025 年中 90% 的线上系统都没做到，因为它们连"当前任务有多难"都没度量。

度量方法其实不复杂：离线拿标注集跑一遍，记录每类任务的"准确率-思考量"曲线，找到拐点；线上按任务类型查表分配预算。拐点右边的每一 token，都是纯成本。

## 为什么会这样：三层原因

**第一层：奖励函数的盲区。** RLHF/RLVR 的奖励只看最终答案对不对。想 100 token 答对和想 10000 token 答对，拿的分一样。梯度下降是聪明的偷懒大师——它发现"多想"能轻微提高答对率，而"少想"没有任何奖励，于是策略收敛到"能想多深想多深"。**这不是 bug，是奖励函数字面意义上的最优解。**

**第二层：没有难度感知的前置模块。** 人类扫一眼题目就知道难度，因为我们有独立的"元认知"：先判断，再分配精力。当前的主流推理模型是端到端的自回归——难度判断如果存在，也只能藏在 hidden state 里，没有显式的、可干预的"预算分配器"。想让模型"先看题再决定想多久"，等于要加一套新的训练信号。

**第三层：行业叙事的推波助澜。** "更多思考 = 更强"是 2025 年上半年最性感的 scaling story。Benchmark 的计分方式（只看准确率不看成本）让所有厂商都没动力踩刹车。直到账单先教育了用户——很多团队的真实路径是：** excited 地用上 o3 → 收到第一张账单 → 默默换回 4o/小模型 → 只在 20% 的难题上用推理模型**。

## 工程上的四条路线

2025 年中，解法沿着四条路线同时推进，本质是"手动挡"到"自动挡"的光谱：

**路线一：预算控制（手动挡）。** Claude 的 thinking budget 是代表：开发者指定"这次最多想 N 个 token"。简单粗暴但有效——客服分类给 1024，代码生成给 8000。缺点是预算要人来拍，拍小了难任务做不出来，拍大了等于没设。实践中大家最后都写成"按任务类型查表"，表越写越长。

**路线二：自适应推理（自动挡）。** 训练模型自己判断难度、动态分配思考量。技术上有两条子路线：(a) 在 RL 奖励里加入"长度惩罚项"，答对的前提下越短越好——但惩罚系数极难调，调大了模型开始"偷工减料"，难题也瞎答；(b) 单独训练一个"难度分类器"，先快后慢。自动挡是长期方向，但 2025 年中的 reality 是：**自动挡还不如老司机手动换挡**，大多数生产系统用的还是查表。

**路线三：早停/剪枝。** 监控思考过程的"信息增益"：如果新增的思考不再改变答案的概率分布，就截断。这很像搜索算法里的剪枝——AlphaGo 也不会把每条路都算到终局。难点在于"答案分布"的度量：思考是隐式的 token 流，你得有个轻量探针实时估计"它是不是已经想明白了"。这条路线在 2025 年还偏研究，但思想会进到下一代推理架构里。

**路线四：蒸馏（把思考变成直觉）。** 大模型用 10K token 想明白的东西，能不能蒸馏成小模型的"第一反应"？o4-mini 这类模型走的就是这条路：**用慢思考训练快直觉**。这对"高频简单任务"是最优解——思考成本一次性付清，推理时零思考。但它有个边界：蒸馏只能压缩"已知模式"的思考，真正的难题（分布外）还是得现场想。

## 算一笔账：过度思考贵在哪

拿一个客服场景算。假设 80% 是简单问题（分类、查单、FAQ），20% 是复杂问题（多步推理、纠纷判断）：

```
简单问题：
  该花：  500 tokens 思考 + 200 输出
  实花： 8000 tokens 思考 + 200 输出  → 贵 16 倍

复杂问题：
  花 8000 tokens 思考，物有所值

加权：0.8 × 16 + 0.2 × 1 = 综合成本是"该花"的约 13 倍
```

而准确率呢？简单问题上，8000 token 和 500 token 的准确率差**不到 2 个百分点**——很多还是噪声。这就是"用上 o3 又默默换回"的经济学真相：**你为 20% 的难题付了 100% 的思考税**。

还有个隐性成本是延迟。思考 token 是串行生成的，8000 token 的思考在高峰期意味着用户多等几十秒。客服场景里，**延迟的流失率杀伤经常大于准确率的收益**——用户不会为"想得很周全但 40 秒后才回复"的客服买单。

## 给开发者的实践清单

**1. 先分级，再选模型。** 用便宜的小模型（甚至规则）做"难度分类器"，把请求分成"快通道"和"慢通道"。只有慢通道才上推理模型。这是 2025 年最有效的省钱手段，没有之一——因为它直接砍掉了 80% 场景的思考税。

**2. 预算永远封顶，默认从小试起。** thinking budget 不要按"难题"设，按"中位数任务"设，难题走升级路径（retry with larger budget）。大部分团队犯的错误是反过来的：先给个巨大的默认预算，然后忘记调小。

**3. 观测 R 值（思考/答案比）。** 把每次调用的思考 token 和答案 token 都打进监控，按任务类型看 R 的分布。R 异常高的任务类型，就是你的优化清单。这比"优化 prompt"实在得多——**你能量化的，才敢动手砍**。

**4. 缓存思考轨迹。** 同类问题的思考过程高度相似，prompt caching / 语义缓存能把重复思考的成本降一个量级。客服、代码补全这类"问题空间收敛"的场景，缓存的 ROI 极高。

o1 范式教会了模型"思考"，但没教会它"什么时候不思考"。下半场的竞争，会从"谁想得更深"转向"谁想得更准"——**知道何时停下，和知道如何深入，是同一种智能的两面**。而在那之前，先给你的 thinking budget 设个上限，今晚就能省下一笔钱。
