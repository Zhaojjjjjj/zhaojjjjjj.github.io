> 注意力矩阵里 99% 的权重接近于 0。稀疏注意力的全部思想就是：别算那 99 亿次浪费。

先建立直觉。Dense 注意力的计算是：

```python
attn = softmax(Q @ K.T / sqrt(d)) @ V   # O(n²)
```

每个 token 看所有 token。但实测的注意力矩阵长这样：**每一行只有几十个显著非零的位置**——当前词真正"注意"的，就是附近的词和几个关键词。剩下的 99900 个位置，softmax 之后≈0，**算了等于没算**。

稀疏化就是把"等于没算"的部分真的不算：

```python
# 稀疏：只算 top-k
scores = Q @ K.T / sqrt(d)
topk_idx = scores.topk(k=1024, dim=-1).indices  # 只取最重要的 1024 个
attn = sparse_softmax(scores, topk_idx) @ V     # O(n×k)
```

但这里有个鸡生蛋问题：**topk 本身要先算出完整的 scores（O(n²)）才能取 top-k**——那稀疏化的意义何在？答案是：用**近似**先粗筛。LSH、聚类、学习到的路由——先用一个便宜的方法猜"谁可能重要"，再对候选者精算。这就是所有稀疏注意力方案的分水岭：**粗筛的质量，决定稀疏化的上限**。

# 一、滑动窗口：最糙，但最有效

```
每个 token 只看前后各 512 个 → O(n × w)，w=1024
```

Mistral 2023 年的做法，基于**局部性假设**：离得近的更相关。简单、快速、工程友好。但代价是**长程依赖会丢**——第 1 个 token 和第 100000 个 token 的关系，窗口永远看不见。

滑动窗口的真正价值不是它本身，而是它证明了一件事：**砍掉 99% 的注意力，模型还能work**。这给了后面所有稀疏方案信心。

# 二、稀疏模式：学术的优雅，工程的累赘

BigBird（2020）：窗口 + 随机 + 全局三种模式的组合，并**理论证明**稀疏可以逼近 dense 的表达能力。

```
BigBird 的注意力模式：
■■■■□□□□□□  ← 窗口（局部）
□□■□□□■□□□  ← 随机（长程采样）
■□□□□□□□□■  ← 全局（几个特殊 token 看所有）
```

理论漂亮，但工程上没人用——**固定的稀疏模式是"一刀切"**，不管内容是什么，都用同一套"看谁"的规则。真实文本里，"谁重要"是内容决定的，不是位置决定的。

# 三、MSA：让模型自己学"该看谁"

MiniMax M3 的 MSA（MiniMax Sparse Attention），从公开信息看，走的是**动态稀疏**路线：

```
不是固定模式，而是 content-based：
每个 query 动态决定"这一轮我要看哪 1024 个 key"
→ 粗筛器本身是可学习的
```

**动态 > 静态** 的核心逻辑：固定的稀疏模式会丢信息（某个关键 token 恰好不在窗口里），而可学习的粗筛器能适应内容。代价是粗筛器本身也要训练、也要推理——**稀疏化的 overhead 必须小于省下的计算**，否则就是负优化。

从公开的数字看（Prefill 9.7x、Decoding 15.6x），MSA 是work的。而且注意一个细节：**Decoding 加速比 Prefill 狠得多**。因为 decoding 是 memory-bound——瓶颈不在计算，在 KV Cache 的搬运。稀疏化直接砍了 90% 的 KV 搬运量，**省的不是算力，是内存带宽**。

# 结语

稀疏注意力的演进史可以浓缩成一句话：

> **从"固定地不看"（滑动窗口），到"理论上可以不看"（BigBird），到"学会该看谁"（MSA）——稀疏化的方向，是让"不看"这个决策本身智能化。**

2026 年，长上下文的竞争从"窗口多大"转向"注意力多稀疏"。记住这个公式：**模型不需要看所有，只需要看对的——而"对的"，可以学出来**。下一个战场是"粗筛器"的设计：谁的粗筛又准又便宜，谁的稀疏化就走得最远。
