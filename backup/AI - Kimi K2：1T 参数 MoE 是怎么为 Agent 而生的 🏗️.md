> Kimi K2 发布于 2025 年 7 月 11 日，1T 参数 MoE 开源，主打 Agent 与代码能力，一度是国产开源的新标杆。这篇从架构角度拆解：万亿参数是怎么做到的，又为什么适合 Agent。

## 参数的账：1T 是怎么"装"下的

首先纠正一个误解：**1T 是总参数，推理时只激活一小部分**。

```
总参数：1T（1,000B）
每 token 激活：约 32B
```

MoE 的数学：384 个专家，每次路由选 8 个。存储要 1T（需要多卡/量化部署），但**计算量只相当于 32B 模型**。这是 MoE 的核心套利——用存储换能力。

对比 dense 1T 模型：推理一次要过 1T 参数，KV Cache 和算力都扛不住。MoE 让"大"和"快"第一次不矛盾。

## 为什么 MoE 适合 Agent

Agent 任务的两个特点，恰好撞上 MoE 的长处：

1. **任务多样性高**：写代码、读文档、调工具——不同的子任务可以路由到不同的专家。Dense 模型要"一个大脑干所有活"，MoE 是"专家会诊"。
2. **长程依赖**：Agent 要记住几十轮的上下文。K2 的 256K 上下文 + MoE 的稀疏计算，让长程任务的成本可控。

Kimi 团队在训练时加了大量 **agentic 数据**（工具调用轨迹、多轮任务），而不是纯文本。这是从"数据"层面为 Agent 优化，不只是架构。

## 训练的工程挑战

训 1T MoE 有三个地狱级难题：

1. **专家负载均衡**：384 个专家，如果路由偷懒（只用前 10 个），等于白训。Aux loss 强制均衡，但调不好会损伤主任务。
2. **通信开销**：专家并行（EP）下，token 要在 GPU 间 dispatch/combine。1T 规模下，all-to-all 通信能吃掉 30% 的训练时间。
3. **稳定性**：MoE 的 loss spike 比 dense 频繁得多。K2 训练中用了更激进的 gradient clipping 和 warmup 策略。

## 开源的意义

K2 开源（modified MIT）后，开发者第一次能**本地部署**一个 Agent 能力顶级的模型：

- 私有化部署的 Agent 应用成为可能（数据不出内网）。
- 微调：1T 太大，但可以用 LoRA 只调激活的专家（见下周的 LoRA 篇）。
- 蒸馏：用 K2 当老师，训小模型。

## 一句话总结

K2 的 1T 不是"大力出奇迹"，是"精确的稀疏"。MoE 架构 + agentic 数据 + 开源，三板斧砍出了 2025 年中国开源模型的最高峰。它的真正遗产是证明了：**Agent 时代，架构比参数量重要**。
