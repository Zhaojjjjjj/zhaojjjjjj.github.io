> MiniMax M3：428B 总参数，23B 激活。存 428B，算 23B——**存储和计算的比值是 18:1**。这是 MoE 走到极致的样子，也是 2026 年开源模型"效率竞赛"的开哨。

先算一笔部署账，因为这是 M3 一切设计的前提：

```
FP16：428B × 2 bytes = 856GB → 8×H100（640GB，不够）→ 得 12 张卡
FP8： 428B × 1 byte  = 428GB → 4×H100，刚好
Q4：  428B × 0.5     = 214GB → 2×H100，或 8×4090（192GB，差一点）
```

**Q4 是甜点，但个人玩家依然够不着。** M3 的开源对象不是极客，是中小公司——"买得起 2 张 H100 的团队"。这个定位，决定了 M3 的所有技术选择都是"**为部署而设计**"，不是"为刷榜而设计"。

# 一、MSA：稀疏化的第一次大规模实测

5 月那篇讲了稀疏注意力的理论，M3 是它的第一次大规模验证：

```
Prefill（输入处理）：   9.7 倍加速
Decoding（逐 token 生成）：15.6 倍加速
```

注意：**Decoding 加速比 Prefill 狠得多**。这是理解 MSA 的关键——decoding 是 memory-bound，瓶颈不在计算，在 KV Cache 的搬运：

```python
# 直观对比（100K 上下文，单次推理）
# Dense：KV Cache 200GB，每生成一个 token 要搬 200GB → H100 跑 8 秒
# MSA：  KV Cache 20GB， 搬运量砍 90%          → H100 跑 0.8 秒
```

**稀疏化省的不是算力，是内存带宽。** 2026 年的推理优化，第一性原理都是这一句：decoding 的瓶颈在"搬数据"，不在"算数"。MSA、GQA、MLA——所有 KV 压缩技术，都是在和内存带宽较劲。

# 二、23B 激活：MoE 的"精确稀疏"

```
总参数 428B，激活 23B → 每次推理只用 5.4%
```

对比 dense 428B 模型：推理一次要过全部 428B 参数，KV Cache 和算力都扛不住。MoE 的套利是**用存储换能力**：存得下 428B 的"知识"，但每次只付 23B 的"计算费"。

但 MoE 有个隐藏成本：**专家负载均衡**。如果路由偷懒（只用前 10 个专家），428B 就白存了。M3 的 MSA 和 MoE 路由是协同设计的——稀疏注意力砍的是"看谁"，MoE 路由砍的是"用谁"，**两个稀疏化乘起来，才是 23B 这个数字**。

# 三、M3 vs V4：开源双雄的分化

|  | M3 | V4-Pro |
|---|---|---|
| 总参 / 激活 | 428B / 23B | 未公开（约 671B 系） |
| 多模态 | 原生（文本+图像+音频） | 文本为主 |
| Agent | 强 | 最强（开源） |
| 上下文 | 1M | 1M |

**M3 赢在多模态，V4 赢在 Agent。** 这不是巧合，是两家公司的基因：MiniMax 起家就是多模态（海螺、语音），DeepSeek 起家是推理（R1）。2026 年中，开源模型的竞争从"谁总分高"变成了"**谁在你的场景强**"——通用榜单的意义在下降，场景榜单在上升。

# 结语

M3 可以浓缩成一句话：

> **2026 年的开源模型，从"参数竞赛"转向"效率竞赛"——谁的架构更稀疏，谁的部署更便宜，谁就有生态。**

428B 存、23B 算，MSA 把内存带宽砍掉 90%，Q4 让 2 张 H100 跑起来。MiniMax 的每一步都在回答同一个问题："**中小公司怎么用得起？**"而开源模型的终极竞争，从来不是"谁的分数高"，是"谁的部署成本低"——因为**用的人多，生态才大；生态大，模型才活得久**。
