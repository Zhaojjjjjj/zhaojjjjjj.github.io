> 蒸馏的反常识结论：让学生看一百道题时老师"犹豫的样子"，比刷一万道题的标准答案学得更多。

# 知识蒸馏：小模型"开窍"的真正原因

训练小模型，最反常识的结论可能是这个：让学生刷一万道题的标准答案，不如让他看一百道题时老师"犹豫的样子"。

最近几个月，小参数模型集体"开窍"：几 B、十几 B 的模型，在代码、数学、指令跟随上逼近上一代旗舰的八九成，速度快几倍，成本只有零头。魔法不在架构——Transformer 还是那个 Transformer。问题是：**知识到底是什么？是"答案"，还是"得出答案时的权衡"？**

# 一、蒸馏蒸的不是答案，是"暗知识"

标准训练是"刷题"：输入和标准答案，用交叉熵把预测往答案上压。蒸馏换了思路：**不直接学答案，学老师的输出分布**。

```
传统训练：  输入 "1+1=?" → 目标 "2"（one-hot：2 是 1，其他是 0）
蒸馏训练：  输入 "1+1=?" → 老师输出 "2"(0.97)、"二"(0.02)、"two"(0.01)、……
```

one-hot 的信息量极低：它只说"2 对"，没说"2 和二很像，2 和苹果完全不像"。老师的软标签里藏着**类间相似度结构**——Hinton 在 2015 年的论文《Distilling the Knowledge in a Neural Network》中称之为"暗知识"（dark knowledge）。

打个比方：传统训练是让学生背标准答案；蒸馏是让学生坐在老师旁边，看老师做每道题时的犹豫和权衡。"这题选 A，但 B 也有三分道理，C 纯属干扰项"——这种"为什么"的知识，信息量是"选 A"的几十倍。

这就是蒸馏效率惊人的根本原因：**每个训练样本携带的信息密度变了**，学生用少得多的数据，学到接近老师的认知结构。

# 二、温度：把分布"捂软"的机制

软标签不是天然就软的。老师输出的 logits 经过普通 softmax，本来就很硬（top1 概率 0.99，其他接近 0）。蒸馏引入**温度 T**：

```python
# T 越大，分布越平坦，暗知识释放得越多
soft_targets = softmax(teacher_logits / T)   # T 通常取 2~8

loss = alpha * T**2 * KL(student_logits / T, soft_targets) \
     + (1 - alpha) * CE(student_logits, hard_labels)
```

两项各司其职：KL 项模仿老师的分布，CE 项别忘了标准答案。`T**2` 是数学补偿——温度把梯度压小了，得乘回来。

**T 太小**：分布接近 one-hot，蒸馏退化成普通训练，等于白蒸。**T 太大**：分布接近均匀，老师说什么都像没说。调蒸馏，先调 T——这是第一超参，优先级比学习率还高。

细节：老师和学生要用**同一个 T**。学生这边的 logits 也要除以 T 再做 softmax，否则两边不在一个尺度上，KL 散度算出来是错的。

# 三、三种配方：条件决定方法

**黑盒蒸馏**：只有老师的 API。种子数据 → 调 API 生成答案 → 训学生。市面上大部分"小而强"的模型都是这么来的。门槛低，但只能学到输出，看不到老师"怎么想的"。

**白盒蒸馏**：有老师的权重。对齐 hidden states、注意力分布，学"中间怎么表征"。学得更深，但要求拿得到权重——对闭源旗舰不适用。

**序列级蒸馏**：不只学单 token 分布，学**整段生成的轨迹**。对代码、Agent 这类长程任务关键：单步都对、连起来错，是小模型的通病；模仿老师完整的推理链，能保住长程连贯性。

没有优劣，只有条件：有 API 用黑盒，有权重上白盒，做 Agent 和代码加序列级。

# 四、真正的护城河：数据配方

很多人以为蒸馏的门槛是"调 T"，其实是**数据**。老师 API 人人调得起，但喂什么数据、怎么过滤输出，决定学生的最终水平。

三条军规：**覆盖目标任务的真实分布**（带上下文、带模糊需求的真题，不是教科书题）；**难度分层**（3:5:2 配简单、中等、困难——全简单则暗知识少，全难则老师自己都错）；**长尾加权**（蒸馏最容易丢的就是长尾知识，权重刻意调高）。

还有个进阶玩法：**让老师"出题"**。不只用现成种子数据，让老师生成变体、构造难例、写测试用例。老师既是出题人又是阅卷人，学生做的是"无限题库"——self-instruct 式的循环，是今年很多小模型数据 pipeline 的标配。

# 五、能力坍缩：蒸馏的阿喀琉斯之踵

单任务上，学生几乎不可能超过老师——蒸馏是压缩，压缩就有损。但有个更隐蔽的风险：**能力坍缩**。

老师会的长尾知识（低频、冷门），在软标签里概率质量很低，学生容易学丢。结果是：**主流任务很强，偏门问题一问三不知**。验证集上 90% 保留率，拆开看可能是头部 95%、长尾 60%——平均数会骗人。

所以蒸馏的验收必须分两套：**总体能力保留率**（85% 及格，90% 优秀），外加**单独的长尾测试集**。不测长尾，等于没测。

# 六、蒸馏 vs 量化 vs 剪枝

"把大模型变小"有三条路线，经常被混为一谈：

```
蒸馏：压缩"知识"（重训小模型）——架构可换，压缩比最高，要训练成本
量化：压缩"精度"（FP16→INT4）——即插即用，压缩比有限（4~8x）
剪枝：压缩"结构"（砍权重）——效果不稳定，依赖硬件加速
```

实战里它们**组合使用**：先蒸馏出小模型，再量化到 INT8。两条路线正交，收益叠加——70B 蒸到 8B（约 9x）再 INT8（约 2x），综合 18x 压缩，能力保留 80% 以上。这是今年"端侧可用"模型的标准配方。

# 结语

蒸馏的本质，是把"标准答案"升级成"老师的犹豫"：

> **知识的密度变了，学习的效率才变。**

这也解释了今年的行业分工：旗舰模型负责探索能力的上限，蒸馏出的小模型负责把上限变成利润。探索上限是科学，压缩上限是工程。而蒸馏，是两者之间最赚钱的那座桥。

落地前记住三件事：**先定老师**（老师决定上限，同系列最强优先）；**数据配方里给长尾留 10~20% 预算**；**蒸馏完再做一轮量化**，压缩比翻倍。
