> 某团队把主力模型换成便宜 70% 的新模型，三个月后 AI 账单涨了 40%。这是 AI 版的杰文斯悖论：效率提升不会减少消耗，只会扩大使用。

先看这个反常的数字：token 单价降了 70%，总账单涨了 40%。如果只看单价，这是不可能的；如果看清账单的构成，它是必然的。

```
月账单 = Σ(每次调用 [输入 token × 输入单价 + 输出 token × 输出单价])
```

输出单价通常是输入的 2-4 倍。而"输出"里的大头，往往不是答案，而是**思考过程**——用户看不见、但账单照付的部分。2026 年要比的，不是单价，而是**完成一个任务的期望成本**。下面三个隐形成本，每个都可能比单价差异大一个数量级。

# 一、思考税：为 12 份草稿纸付费

推理模型的特点是想得越久答得越好，但不同任务的"思考/答案比"天差地别：

```
简单问答、分类：      思考 ~100 token    答案 ~100 token    1x
代码生成：            思考 ~2,000 token  答案 ~500 token    4x
数学证明、复杂规划：  思考 ~10,000 token 答案 ~800 token    12x
```

12 倍意味着：你在为 12 份"草稿纸"付费，只为了 1 份"答卷"。而便宜模型诱使你"反正便宜，多想想也无妨"——**单价降了，使用量涨了，总账单涨了**。这就是开头的 40% 从哪来的。

对策不是换更便宜的模型，而是**按难度路由**：

```python
# 难度分类器：小模型，几乎免费
difficulty = classifier.predict(user_input)

if difficulty == "easy":
    return cheap_model(user_input)          # 70% 的流量，快 5 倍，便宜 10 倍
elif difficulty == "medium":
    return thinking_model(user_input, budget=2000)
else:
    return flagship_model(user_input)       # 只有 5% 值得烧钱
```

分类器本身的成本忽略不计，但能把 70% 的简单请求从"思考税"里摘出来。**省钱的第一性原理：让贵的模型少干活。**

# 二、重试税：便宜模型的级联代价

弱模型单价便宜，但一次成功率 70%；强模型贵 3 倍，一次成功率 95%。算期望成本：

```
弱模型期望成本 = 1.0 × (1/0.70) ≈ 1.43
强模型期望成本 = 3.0 × (1/0.95) ≈ 3.16
```

看着弱模型赢了？别急着下结论。重试还有两笔账，单价公式里没有：

**延迟成本**：每次重试都是一次完整往返。在实时交互场景，多一次重试就是多 3-5 秒等待。用户流失的代价，远比 token 贵——**省下的 token 钱，不够付流失的用户**。

**级联成本**：在 Agent 链路里，一步失败会导致整个链条重跑。一个 5 步的 Agent，每步成功率 90%，整体成功率只有 0.9^5 ≈ 59%。这时候**每一步都值得用强模型**——短板效应下，最弱的那步决定了总成本。用弱模型"省钱"，实际是在为 41% 的失败率买单。

对策：给每个任务设"一次成功率"指标，和单价一起看。核心链路用强模型保成功率，边缘任务用弱模型省单价。** reliability 是成本的一部分，不是质量的可选项。**

# 三、上下文税：为"以防万一"交的两种税

长上下文的 input token 看似便宜，但有两个隐藏代价：

**计算代价**：attention 是平方级复杂度。128K 上下文的首 token 延迟，可能是 4K 上下文的 10 倍以上。你为"以防万一"塞进去的文档，每次调用都在交税——交的不是 token，是延迟。延迟在交互场景里，就是钱。

**注意力稀释**：上下文越长，模型越容易忽略关键信息。你塞了 100 页文档，模型可能恰恰没看到第 37 页的那行关键配置。**塞得多 ≠ 记得多**，这和记忆那篇讲的是同一个道理。

对策：该 RAG 的别硬塞；prompt caching 让重复的 system prompt 只算一次钱；定期做"上下文审计"——看看 prompt 里有多少 token 是从来没被模型"注意"过的。

# 四、一个完整的算例

客服问答场景，日均 1 万次会话：

```
方案 A：单一强模型
  单次期望成本 ≈ ¥0.0279（含重试）
  月成本 ≈ ¥8,370

方案 B：路由 + 缓存 + 弱模型打底
  70% 简单问题走弱模型，30% 走强模型
  单次期望成本 ≈ ¥0.013
  月成本 ≈ ¥3,900
```

差了一倍多。而单价差异只有 3-5 倍——**真正的差距来自路由和缓存的乘数效应**，不是单价本身。

# 结语：降本检查清单

下次 review AI 账单时，按这个顺序查：

1. **路由**：有没有按难度分流？多少简单请求在烧思考模型的钱？
2. **缓存**：system prompt 和静态文档的缓存命中率是多少？低于 80% 就是漏水；
3. **重试率**：整体重试率超过 10%？先提成功率，再谈单价；
4. **上下文**：平均输入 token 是不是在悄悄变长？设个告警线；
5. **影子测试**：新模型上线前，先切 5% 流量对比"任务完成成本"，别只看单价。

最后是个反直觉的结论：**2026 年最省钱的策略，往往不是用最便宜的模型，而是让最贵的模型少干活**——把 70% 的请求挡在它前面，剩下的 30% 让它一次做对。省钱的本质是减少浪费，不是压低单价。杰文斯悖论说的是：效率提升会扩大使用；但**路由说的是：你可以决定把效率用在哪**。
