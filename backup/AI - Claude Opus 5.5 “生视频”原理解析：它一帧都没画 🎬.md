最近 "Claude Opus 5.5 生成视频" 刷屏了：28 秒的 risograph 风动画、《果蝇的一生》、甚至马斯克转发的 5 分钟 MV。但先说结论：**Opus 5.5 根本不会"画"视频，它交出来的是一份代码** —— 画面是浏览器照着代码一帧一帧算出来的。

## 不是文生视频，是"代码生视频"

传统文生视频（Sora、Veo、Seedance 这类）：提示词 → 扩散模型直接算出像素 → 你拿到一段 MP4，画面不可拆、不可改。

Opus 5.5 的路子完全不同：

> 提示词 → 模型写出 HTML/JS（或 Python）动画程序 → 无头浏览器逐帧渲染截图 → FFmpeg 压成 MP4

Anthropic 官方从来没把这当功能宣传（发布公告里没提视频半个字），是社区自己摸索出来的。正如有人总结的：**"它一帧都没生成"，这个说法是准确的。**

## 四步管线

1. **写场景代码**：模型和渲染器约定一个接口 —— "给我时间 t，我画出 t 时刻的画面"。Claude 负责设计场景、规划分镜、写动效节奏，输出常常是单个 HTML 文件（Canvas 2D 程序化绘制 + Web Audio 合成的音乐，还能和画面对拍）。
2. **逐帧渲染**：无头 Chromium 把时间拨到第 0 帧、1 帧、2 帧……每拨一次截一张图。
3. **编码**：截图序列喂给 FFmpeg，打包成 H.264 MP4。
4. **检查-重渲染**：抽几帧出来"看"，有 bug（JS 报错、文字错位）就改代码重跑 —— 这一步恰恰是 LLM Agent 最擅长的。

开源实现里有个叫 LaunchVideo（仓库名 shipvideo）的项目把 README 写得最直白，开头就是 "No video model"。

## 为什么偏偏是现在？

- **长上下文**：一次吞下完整分镜规划 + 大几千行动画代码，风格不跑偏
- **Agentic coding**：能自己跑、自己看报错、自己改，渲染管线天然适合 agent loop
- **规划能力**：把"28 秒短片"拆成 40 多个视觉段落（plates），转场和节奏都排好

## 它能做什么，不能做什么

能：动态图形、产品发布片、科普动画、数据可视化、歌词 MV —— **凡是能用代码描述画面的**，都行，而且每个元素可改、可重渲染。

不能：真人实拍感、自然口型、照片级写实 —— 代码画不出来。常见搭配是视频模型出素材，Opus 负责编排剪辑。

## 一句话总结

Sora 们是在"想象像素"，Opus 5.5 是在"编写世界运行的代码"。一个是画家，一个是导演 + 引擎程序。两种"生成视频"，名字一样，完全是两件事。
